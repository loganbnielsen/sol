`sol deploy` doesn't print the service URL; `sol status` doesn't show the deployed image tag (EXP-021 fix reverted, never refixed)

**Description:** `cmd_deploy.ml` still ends with `Printf.printf "\nDone. %d service(s) deployed.\n" (List.length services)` — no service URL printed. `sol_cli_status.ml` (124 lines) has no image/version field anywhere in its output. This is the original EXP-021 finding. That fix was merged (`e7826793`) then reverted the same day (`92fd2c85`, "Revert 'Merge branch 'EXP-021/deploy-status-url'''") after a test failure (`b3679a83`, "pipeline: test failure blocked EXP-021"), and was never refixed — the ticket still sits in `project/tickets/DONE/EXP-021.md` describing a fix that no longer exists in `main`.

**Impact:** After `sol deploy`, the engineer needs a separate `sol status` call to discover the endpoint. After `sol status`, they cannot confirm which image/version is actually live without `kubectl` knowledge, making it harder to verify a rollout completed correctly.

**Remediation:** In `cmd_deploy.ml`, after deploying, query the Kubernetes Service for each HTTP service and print its port-forward hint or URL (same logic `cmd_status.ml` already uses for its own output). In `sol_cli_status.ml`, add an image-tag column to the pod output (e.g. via `-o jsonpath`/custom-columns on `spec.containers[0].image`). Before merging, run the full test suite locally first — the original fix's test failure was never diagnosed.
