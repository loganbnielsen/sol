README Quickstart install command 404s against the only published GitHub release

**Description:** README.md's Quickstart instructs `curl -L .../releases/latest/download/sol-vX.Y.Z-linux-x86_64.tar.gz`. The only published release, `v0.1.0-alpha.6` (2026-06-11), predates the `sun`→`sol` rename (FEAT-032) and ships its asset as `sun-v0.1.0-alpha.6-linux-x86_64.tar.gz`, not `sol-...`. Verified live: the `sol-`-prefixed URL returns HTTP 404; the `sun-`-prefixed one returns 200. `.github/workflows/release.yml` was already updated post-rename to build `sol-${VERSION}-...` bundles, but no release has been cut since, so this is a real, currently-reproducible gap. Separately, `sol --version` always prints the literal string `"dev"` (`Cmdliner.Cmd.info "sol" ~version:"dev"` in `cli/sol/bin/main.ml`), so there is no way to confirm the installed build's actual version even after a successful install.

**Impact:** Following the README's Quickstart exactly as written fails at the very first command with a 404 (curl piping an HTML error page into `tar` produces an opaque gzip error, not an actionable message). This blocks Stage 1 of the UX audit's golden path entirely — it is the first thing any new user does.

**Remediation:** Cut a new release (push a `v*` tag) using the current `release.yml`, which already builds and publishes correctly-named `sol-`-prefixed assets. This is a release-cut action (visible, public), not just a code change — confirm before pushing a new tag. Separately, fix `~version:"dev"` in `cli/sol/bin/main.ml` to embed the real build version (e.g. derived from the git tag or `git describe` at build time) so `sol --version` is meaningful.
