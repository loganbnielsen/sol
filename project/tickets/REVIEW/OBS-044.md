**Depends on:** None.

No dashboard exists for the RDS instances Sol provisions — `observability-design.md`'s "Dashboard Shape" list (workspace/domain/service/deploy-timeline) only covers application services, not managed infrastructure resources.

**Description:** `platform/infra/aws/main.tf` provisions `aws_db_instance.postgres` with no CloudWatch alarms, no `performance_insights_enabled`, and no dashboard wiring. The only Grafana dashboard shipped anywhere in the repo (`platform/local/config/grafana-dashboards/sol-demo-overview.json`) covers the demo app's own service metrics; it has no RDS-specific panels. A user has no way to see RDS CPU/connections/storage/IOPS without leaving Sol entirely for the AWS console — which cuts directly against the "you shouldn't need to learn AWS" positioning in `docs/architecture/PRODUCT_ARCHITECTURE.md`'s hosted-factory-floor direction.

**Impact:** RDS is silently unobserved. A connection-pool exhaustion or storage-full event surfaces only as an application-level outage with no lead-time signal and nothing to correlate it against — exactly the cross-domain incident correlation `observability-design.md` says is "the point" of the shared dashboard surface.

**Remediation:** Extend `observability-design.md`'s "Dashboard Shape" section to add a "managed resource dashboard" tier alongside workspace/domain/service, then implement it for RDS first:
1. Terraform: provision a CloudWatch-backed dashboard alongside `aws_db_instance.postgres` (CPUUtilization, DatabaseConnections, FreeStorageSpace, Read/WriteIOPS), wired into Grafana via its CloudWatch datasource.
2. Surface it through `sol status`/`sol open dashboard`'s existing label-scoped surface rather than a standalone URL the user has to discover separately.
3. Design the provisioning mechanism generic by resource type, not RDS-specific, so any future managed datastore gets the same dashboard without a second one-off implementation.

**Acceptance criteria:**
- A real `terraform apply` against AWS shows a working RDS dashboard reachable via `sol open dashboard`.
- No DynamoDB work is included in this ticket — no `aws_dynamodb_table` resource exists anywhere in this repo (confirmed via grep of `platform/infra/aws/main.tf`); a DynamoDB dashboard has nothing to attach to and stays out of scope until DynamoDB provisioning itself is a real feature.
