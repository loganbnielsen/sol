`sol cloud init` still has no kubeconfig auto-run or explicit follow-up instruction (EXP-023 fix reverted, never refixed)

**Description:** `cmd_cloud.ml` prints the Terraform `kubeconfig_command` output but neither runs it automatically nor is followed by an explicit "run this before continuing" instruction in the CLI output or docs. This is the original EXP-023 finding. That fix was merged (`2292a17c`) then reverted the same day (`3ece9e8c`, "Revert 'Merge branch 'EXP-023/cloud-init-kubeconfig'''") after a test failure (`9c31e9a3`, "pipeline: test failure blocked EXP-023"), and was never refixed — the ticket still sits in `project/tickets/DONE/EXP-023.md` describing a fix that no longer exists in `main`.

**Impact:** An engineer who misses the `kubeconfig_command` output line finds `sol status`/`sol deploy`/`sol migrate` failing because `kubectl` has no cluster context, with no guidance pointing back at the command they need to run.

**Remediation:** Either auto-run the `kubeconfig_command` from `cmd_cloud.ml` after printing Terraform outputs (printing a clear "Configuring kubectl…" message first), or add an explicit instruction immediately after the printed command in both the CLI output and README/TUTORIAL Part 8. Before merging, run the full test suite locally first — the original fix's test failure was never diagnosed, so whatever caused it is still unknown.
