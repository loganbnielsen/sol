# FND-0014 — Release pruning lists ConfigMaps the deploy identity may not list

- **Classification:** `VERIFIED_DEFECT`
- **State:** `OPEN`
- **First identified:** 2026-09-20, AWS Run 8 step 6 (live; a warning, not a failure)
- **Derived ticket:** `INFRA-051`
- **Invariant:** `INV-AUTH-6` (an identity Sol provisions may do everything Sol does as it) — the same shape as FND-0011
- **Evidence class:** `BEHAVIORAL` (live) + `STATIC` (the Role's verbs)

## The observation

Every successful deploy ends with a warning:

```text
warning: could not prune old releases: kubectl get configmap failed:
Error from server (Forbidden): configmaps is forbidden: User
"arn:aws:sts::<account>:assumed-role/sol-qual5-deploy/EKSGetTokenAuth"
cannot list resource "configmaps" in API group "" in the namespace "default"
```

## Why

Release records live in `default`, and the deploy identity reaches them through a
deliberately narrow exception
(`cli/platform/infra/base/platform_deploy_rbac.tf`, `sol_boundary_lease`):

| Rule | Verbs |
|---|---|
| `configmaps` in `default` | `create` |
| `configmaps` in `default` | `get`, `update`, `delete` |

`list` is absent **on purpose** — the same comment that explains the
create-only namespace grant explains this: the grant is scoped to the operations
`Sol_cli_boundary_lease` issues, by name, because the lease name is generated by
the implementation rather than known at platform-install time.

Pruning, however, is a *discovery* operation: it asks which release records exist
rather than addressing one it already knows. `kubectl get configmap` is a `list`,
so it is refused, and the pruning silently does not happen.

## Why it matters, and why it is not urgent

Non-fatal: the deploy succeeds and the workload runs. But the consequence is
unbounded — release records accumulate in `default` for the life of the target,
and a mechanism the profile relies on (rolling back to a recent release) is
degraded in a way that reports itself only as a warning an operator may never
read. A warning is also not a qualification result: nothing in the matrix records
"pruning did not happen".

## Not yet decided

Two readings, with different fixes:

- **Broaden the exception** to `list` on `configmaps` in `default`. Small, but it
  widens the one boundary the file argues hardest for, and a `list` cannot be
  name-scoped — the same limitation the boundary-lease comment already describes
  for `create`.
- **Keep the boundary and change the mechanism**: have Sol record the release set
  where it can read it by name (the workspace Secret or the boundary lease
  ConfigMap it already owns), or make pruning advisory-with-diagnosis rather than
  a silent skip.

This is a contract decision, not a code detail, so the ticket's first task is to
pick one. Deliberately not fixed during Run 8.
