id: SEC-011
type: audit-finding
severity: low
title: sol deploy can build and push the migration-runner image when run from a checkout
source: REFAC-139 (moving the deployer's code into cli/lib made the path visible)
---

**Depends on:** None.

`sol deploy`'s migration prerequisite check (AUDIT-069) runs the migration runner as a Job, and when Sol runs from a source checkout the runner image is built and pushed on the way. ADR 0002's identity table says the deployer "must not publish/replace images".

## Open Questions

Is Sol's own migration-runner image an *application artifact* in ADR 0002's sense? If it is, the deploy path must use a published runner (or refuse without one). If it is not — it is Sol's tooling, not the workspace's — the ADR's deployer row should say so, and the boundary guard should name the exception rather than miss it.

## Evidence

The path, at the REFAC-139 merge:

```
sol deploy (apply, production profile)
  -> Sol_cli_migration_gate.verify
  -> Sol_cli_migration_gate.read_applied
  -> Sol_cli_migration_job.runner_image
       Build_from_source -> Sol_cli_docker.build, Sol_cli_docker.push
```

```
$ rg -n 'Sol_cli_docker\.(build|push)' cli/lib/deploy/sol_cli_migration_job.ml
111:           Sol_cli_docker.build ~tag:image ~dockerfile ~context
119:      Sol_cli_docker.push ~image_ref:image
$ rg -n 'runner_image' cli/lib/deploy/sol_cli_migration_gate.ml
96:  let* image = Sol_cli_migration_job.runner_image ~registry ~workspace ~k8s_name in
```

An installed release takes `Published` (`Sol_cli_platform_assets.migration_runner`: "An installed release uses the image published with it … and nothing else"), so the crossing happens only in checkout mode. `internal/ci/check_publisher_deployer_boundary.sh` checks the deployer's own files by name, so it does not see a call two modules away; this predates REFAC-139 (the path used to run through `Cmd_migrate`).

## Remediation

Decide the question above; then either route checkout-mode deploys to a pre-built runner (and refuse without one), or record the exception in ADR 0002 and in the guard.
