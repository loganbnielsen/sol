Pluto's deploy targets reference a file outside the workspace boundary.

**Found by:** copying `examples/pluto` to `/tmp/sol-proof/ocaml-workspace` and
asserting there are no escapes out of the workspace. Two targets failed the
assertion:

```text
examples/pluto/sol/dev/aws/us-east-1.yml:4:
  terraform_var_file: ../../cli/platform/infra/aws/smoke-test.tfvars
examples/pluto/sol/customer_cloud/aws/us-east-1.yml:4:
  terraform_var_file: ../../cli/platform/infra/aws/smoke-test.tfvars
```

`../../cli/platform/infra/aws/smoke-test.tfvars` resolves to
`cli/platform/infra/aws/smoke-test.tfvars` inside the **Sol repository**. That
path does not exist in a copy of the workspace (`sol/../../cli` is absent), so
`sol deploy dev/aws/us-east-1` from a standalone workspace cannot find its
terraform variable file. `examples/venus` is unaffected.

**Invariant this violates:**

> A Sol workspace's target configuration must not reference files outside the
> workspace boundary unless the user explicitly configured an external path.
> Sol-provided example targets must be self-contained.

**Why this is not a general prohibition on `../`.** A user pointing a target at a
tfvars file they maintain elsewhere is a legitimate, explicit choice. This case is
different: the reference is not user-configured, it is an artifact of Pluto living
inside the Sol repository and borrowing this repository's smoke-test fixture. The
example is simply invalid under the standalone-workspace contract that DEC-024
describes and that DEC-025/FEAT-085 established for build dependencies. Nothing
needs to be forbidden in general; the example needs to be self-contained.

**Relationship to FEAT-085:** FEAT-085 is scoped to *build* independence and is
not blocked by this. DEC-024's workspace-independence idea is broader than
language/package distribution, though:

```text
standalone workspace
├── build dependencies        ← FEAT-085
├── application source
├── Sol config
└── deployment configuration  ← this ticket: one repo reach-back remains
```

**Remediation:** make the two Pluto targets self-contained. Either ship the
needed variables inside the workspace (e.g. `sol/dev/aws/smoke-test.tfvars`) and
reference them relatively, or drop the `terraform_var_file` key and let the
target use defaults. Whichever is chosen, the example must build *and deploy*
without the Sol repository present.

**Acceptance criteria:**

- No file under `examples/*/sol/` references a path outside its own workspace.
- A copied `examples/pluto` can run `sol deploy dev/aws/us-east-1` (or the
  equivalent target validation) with no Sol checkout on disk.
- The copied-workspace proof asserts this, so a future `../../cli/...` regression
  fails automatically rather than being rediscovered by hand.
