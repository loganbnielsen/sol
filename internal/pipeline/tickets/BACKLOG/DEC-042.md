## Question

GCP TLS issuance is `BLOCKED` because cert-manager's ACME **DNS-01** challenge
needs a DNS zone the qualification project is *authoritative* for. Today the
placeholder is `sol-qual.dev`, which is not delegated to `sol-qualification`, so
any `_acme-challenge` record the project creates is invisible to the CA and the
challenge can never complete (`FND-0007`).

The owner controls **`sol-fab.dev`**. The question is not *whether* a name can be
found, but **which name is delegated, to whom, and how narrowly** — because a
delegation is a real grant of authority over part of a domain's namespace to a
disposable qualification project.

## Options

- **A. A dedicated subdomain of the product domain, delegated to the
  qualification project.** Recommended — see below.
- **B. A separate qualification-only domain.** Cleanest separation, but another
  registration and renewal to own for a name used by no product surface.
- **C. Consume operator-managed records (external DNS operator).** Sol is handed
  records rather than a zone; the cert-manager `ClusterIssuer` still needs a
  solver, and the qualification then depends on a human/other system per attempt.
  This is the inventory's documented alternative, not a way to avoid needing a
  name.
- **D. Accept the gap.** Record the TLS row `BLOCKED`/`ACCEPTED` permanently and
  qualify GCP without a public-TLS capability.

## Recommendation: A, with these scoping rules

1. **Delegate exactly one name** — e.g. `qual.sol-fab.dev` — by NS records at the
   registrar/parent zone pointing at a Cloud DNS managed zone in
   `sol-qualification`. **Never delegate the apex or a name the product itself
   serves** (`sol-fab.dev`, `www`, `api`, mail, etc.).
2. **Scope the IAM to the zone, not the project.** cert-manager gets a dedicated
   service account bound (via Workload Identity) to a role carrying only the
   Cloud DNS change permissions on *that* zone — nothing project-wide. The
   qualification project must not be able to write to the apex zone.
3. **Stage, then produce once.** Qualify against the ACME **staging** directory
   first (no rate-limit risk, no public CT entry for throwaway hosts), then a
   single **production** issuance for the row's evidence — the row is "public TLS
   issuance", so staging alone is mechanism, not qualification.
4. **The delegation is the whole grant and is revocable**: deleting the NS
   records ends it, with no residual authority in the qualification project.

## Why this is appropriate (not an abuse of the product domain)

- It is precisely what the inventory already requires: *"control of a
  qualification subdomain; either delegated Cloud DNS nameservers or an external
  DNS operator; … a publicly resolvable hostname …"*.
- A **dedicated subzone confines the blast radius**: the qualification project can
  answer only for `qual.sol-fab.dev`. A misconfigured or compromised qualification
  project cannot affect `sol-fab.dev` or any product name — the same
  install-authority-bounded-to-a-window discipline ADR 0003 applies to
  credentials, applied to DNS authority.
- It **raises fidelity rather than lowering it**: the target's `base_domain`
  becomes a real, publicly-resolvable name with a real publicly-trusted
  certificate, which is the production shape the profile exists to prove.

## Roadmap fit

This is one HARDEN-004 row, not the whole GCP workstream: the identity/authority
rows and reaching platform `Ready` do not need it and should proceed in parallel.
But it is a genuine step on the "real-world ready" line — it is the **first time
Sol issues and serves a publicly-trusted certificate from an owned domain**, and
it is coupled with the other half of FND-0007 (replacing the hard-wired Route 53
DNS-01 solver with a Cloud DNS solver). GCP parity (HARDEN-004) plus the AWS
workload path (HARDEN-002) together feed `PROD-001`, the first maturity-A pilot.

## Acceptance criteria

- The delegated name and its Cloud DNS zone are recorded, with the NS delegation
  and the exact IAM grant stated, and a note that the product's own names are
  untouched.
- A qualified Cloud DNS solver replaces the Route 53 solver on the GCP path
  (the second half of FND-0007), with a scoped workload identity.
- Staging issuance observed, then one production issuance recorded as the TLS
  row's behavioural evidence.
- The qualification project is demonstrated (or argued with evidence) able to
  write only within the delegated subzone.
