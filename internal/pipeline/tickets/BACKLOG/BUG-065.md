**Depends on:** None.

## The gap

`internal/ci/check_unconditional_guard_tooling.py` (BUG-064) asserts that every
unconditional guard step has its dependencies provided without the conditional
product build. Its requirement signal for tools is `command -v <tool>` in a shell
guard. A guard written in Python asks the same question differently --
`shutil.which("terraform")` -- and that signal is invisible to the check.

Concretely: `internal/ci/check_production_infra.py` shells out to `terraform`
(landed with #629) and is an unconditional step. It happens to be safe, because
`terraform` comes from the runner image and is present in every job, including the
docs-only ones -- which is exactly why the provider set in the guard now names
only the tools the workflow itself installs (kubectl, shfmt, ocamlformat) rather
than every tool a guard mentions. The gap is what happens next: a *Python* guard
that hard-requires a tool the workflow installs (a pinned binary, an opam
installation) would fail on a docs-only change, and this check would not catch
it -- the same class of composition defect BUG-064 fixed, one level down.

## Why it is not a defect to fix by extending the regex

`shutil.which` does not distinguish a hard requirement from a tolerated absence.
`check_production_infra.py` degrades gracefully when `terraform` is absent (it
reports that the format check did not run) while a guard that cannot do its job
without its tool should fail loudly. A signal that treats both the same would
either accept a real gap or reject a legitimate one, so the remedy needs a way to
state which kind a requirement is -- for example a small declared table in the
guard, or a convention for how a guard announces a hard dependency.

## Acceptance criteria

- A Python guard's hard tool requirement is either detected as a requirement or
  explicitly declared as satisfied by the environment, with a mutation case that
  fails the check when that requirement's provider becomes conditional.
- The tolerance distinction is stated where a guard author will read it.
