`@sol-fab/jobs` leaves a lease-renewal sleep dangling, keeping the Node event loop alive up to `leaseS/3`

**Depends on:** None.

**Related:** FEAT-126 (`@sol-fab/jobs`), `loganbnielsen/sol-typescript`.

## Problem

`runJobs` renews a claimed job's lease from a background heartbeat
(`packages/jobs/src/index.ts`):

```ts
const renewal = (async () => {
  while (renewing) {
    await sleep(leaseS / 3);
    ...
  }
})();
...
finally {
  renewing = false;
  void renewal.catch(() => {});
}
```

When a handler finishes, `renewing` is cleared but the in-flight `sleep` is not
cancellable and the promise is not awaited. `DEFAULT_LEASE_S` is `300.0`
(`packages/jobs/src/index.ts:40`), so the production `defaultSleep` arms a
`setTimeout` for 100 s; the abandoned timer keeps the Node event loop alive until
it fires.

## Evidence

Observed while integrating FEAT-124, from `examples/pluto/app/demo_ts` with a
real Postgres:

```text
$ time node --import tsx --test test/outbox.test.ts   # no jobs runner
real 1.4s

$ time node --import tsx --test test/delivery.test.ts  # runs runJobs
real 1m41s
```

Both files report every case passing in under 100 ms; only the file that calls
`runJobs` lingers, and the delay is exactly `DEFAULT_LEASE_S / 3`. `npm test`
reports `# duration_ms 100991`. A `--test-force-exit` run has no delay.

## Impact

Bounded but real. `@sol-fab/worker`'s `runWorker` calls `process.exit` after its
shutdown hooks, so a deployed worker exits promptly. But any embedder that runs
`runJobs` without calling `process.exit` — a test harness, a script, an app that
lets the process exit naturally — stays alive for up to `leaseS/3` (minutes at
the default) after the last job, and the timer is armed for a query that can
never run (`renewing` is already false).

## Remediation

Make the renewal wait not hold the event loop. A small, targeted option: give
`sleep` an optional `AbortSignal`, race the timer against it in `defaultSleep`,
and have `runHandler` abort it in its `finally` (the injected `sleep` used by
tests ignores the extra argument, so tests are unaffected). Equivalently,
`unref()` the renewal timer. Either way the main poll sleep's semantics stay as
they are.

## Acceptance criteria

- `runJobs` returns and leaves no timer armed after the last in-flight handler
  completes.
- A test observes it: run `runJobs` in a subprocess (or with the real `sleep`)
  with `maxJobs: 1` and assert the process exits without waiting `leaseS/3`.

## TypeScript parity

TypeScript-only. The OCaml `Sol_jobs` has no equivalent background timer, so
this is an implementation detail of the TS package and changes no cross-language
contract (`internal/pipeline/audits/2026-10-02_cross_language_contract_audit.md`
row 15 stays `implemented`).
