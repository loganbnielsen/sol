A docs-only PR runs the full test suite while its base's validator cache is still being saved

**Depends on:** None.

**Premise verified (2026-10-02)** against `origin/main @ f4d5b81f`:
`rg -q "docs_tooling.outputs.cache-hit != 'true'" .github/workflows/ci.yml` finds
the product steps' condition
(`needs.classify.outputs.kind != 'docs-only' || steps.docs_tooling.outputs.cache-hit != 'true'`),
which makes the full suite the fallback for a validator-cache miss.

## Problem

A change whose every path is in the docs-only allowlist (`docs/**`,
`internal/pipeline/tickets/**`, `*.md` outside `.github/**`,
`internal/tooling/perf/perf_baseline.json`) still runs the product build, every
guard, and the unit/integration/smoke suites whenever the exact-source ticket
validator cache misses. The gate is

```
needs.classify.outputs.kind != 'docs-only' || steps.docs_tooling.outputs.cache-hit != 'true'
```

so the cache miss — not the classification — selects the full suite. Observed on
PR #880 (a one-file ticket filing): `classify` reported `docs-only`, the
restore step logged `Cache not found for input keys:
soldev-validation-v1-Linux-6ec56c98…`, and the `test` job then built and ran the
whole product suite for ~15 minutes.

The miss is a race, not an edge case. The cache is written only at the *end* of a
push-to-`main` `test` job, after the full suite. A PR opened against a fresh
`main` therefore computes a key whose save has not happened yet and misses; the
key `6ec56c98…` corresponding to `102e2c27` was still absent at 16:34, while
`main`'s post-merge job ran the cache save around 16:49. With several merges
landing in sequence this repeats, so ticket-only and documentation PRs pay the
full product suite.

A docs-only diff cannot affect the product by construction, so the suite buys
nothing; and the fallback was chosen to guarantee `pipeline validate`, which does
not need the suite.

## Desired invariant

Classification alone decides whether the product suite runs. The validator cache
decides only how the docs-only ticket check is supplied — a miss falls back to
the most recent main-built validator, never to the product suite. Only an
uncertain classification takes the full path (unchanged, fail-closed).

## Remediation

- Gate every product/suite step on `needs.classify.outputs.kind != 'docs-only'`;
  no step falls through to the suite for a cache miss.
- Add `restore-keys: soldev-validation-v1-${{ runner.os }}-` to the docs-only
  validator restore. A docs-only diff cannot change the validator's source
  (any change to `internal/tooling/soldev/**`, `internal/tooling/sol_process/**`
  or the pin files would classify as `source`), so the most recent main-built
  validator is exact-source for it; the exact key is still preferred.
- Run `pipeline validate` whenever the classification is docs-only and the
  validator is present; if a total miss left none, emit a warning naming the
  skipped check and still never run the suite.
- Update `internal/ci/check_unconditional_guard_tooling.py` and its mutation test
  to model the classification-only gate and the allowed prefix fallback.

## Acceptance criteria

- No step's condition combines the classification with `cache-hit`; the product
  suite runs exactly when `kind != 'docs-only'`.
- A docs-only run with no cached validator skips `pipeline validate` with a
  visible warning and runs none of the product suite.
- `check_unconditional_guard_tooling.py` and
  `test_unconditional_guard_tooling.sh` pass on the real workflow.
- Demo/example: not applicable — CI only. Language parity: no application-facing
  contract change.

## Completion notes

Landed in PR #881. Product/suite steps are now gated on
`needs.classify.outputs.kind != 'docs-only'` alone; the docs-only validator
restore falls back by key prefix to the most recent main build (a docs-only diff
cannot change its source, so any main build is exact-source for it), and
`pipeline validate` runs whenever a validator is present, warning visibly on a
total miss instead of running the suite.

Guards updated and green: `check_unconditional_guard_tooling.py`,
`test_unconditional_guard_tooling.sh`, and `test_docs_only_path.py` — the paired
Python suite now asserts that no `docs-only` condition mentions `cache-hit`, and
that the prefix fallback stays inside the trusted key namespace.
