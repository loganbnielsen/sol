**Depends on:** None.

Licence Sol's public repository — and thereby make "self-host if you like" a real offer rather than a slogan.

**Question:** The repository is public and carries no `LICENSE`, while the README's opening line calls Sol "open-source". With no licence, default copyright applies: nobody may legally use, copy, modify or distribute Sol. That makes the free self-host pole of the positioning unavailable to everyone but the author, and puts an inaccurate claim in a public README. What licence should the repo carry?

**Context:** The positioning is open-core — free self-hosted software, paid managed service. The paid product is *operations* (Sol runs the box, plus SLA, compliance and team features), not the code. A licence governs code that is distributed; a service is not distributed. Vercel draws exactly this line: Next.js is MIT, the Vercel CLI is Apache-2.0, and the platform itself is proprietary and never licensed to anyone. Copyleft (Grafana's AGPL) exists to stop a cloud reselling the *software* as a service — a risk that doesn't apply when the paid tier isn't the software.

**Options considered:** Apache-2.0 · MIT · AGPL-3.0 core · FSL/source-available. (A permissive core plus proprietary hosted components is a *structure* available under any of them, not a licence choice.)

**Decision:** **Apache-2.0** for the repository.

Chosen over MIT for the explicit patent grant and the trademark/NOTICE clause — MIT is silent on trademarks, which is worse than explicitly excluding them. Chosen over AGPL/FSL because copyleft would buy nothing here (the paid tier is a service, not distributed code) while adding enterprise-legal friction and weakening the "no lock-in" claim. This mirrors Vercel's split: permissive on everything that drives adoption, proprietary on anything hosted — and hosted components stay out of this repository.

**Implemented:**

- `LICENSE` — verbatim Apache-2.0, with the copyright holder filled in.
- `package.json`, `packages/sol-kafka/package.json`, `packages/sol-obs/package.json` — `"license": "Apache-2.0"`.
- `README.md` — the opening line no longer defines Sol as an "OCaml software factory" (it is language-agnostic: OCaml first-class, TypeScript in-tree), and a License section points at `LICENSE` and notes the name and logo are excluded.

**Implications and follow-ups** — tracked in INFRA-007:

- The copyright holder is currently the individual author; if an entity is formed, the copyright should be assigned to it.
- Contributions need a **DCO (or CLA) before any outside code lands**. This is what preserves the ability to relicense a future component, and it is trivial now while the author owns 100% of the repository.
- A dependency licence audit is outstanding — including that the platform deploys Grafana, Loki and Tempo, all **AGPL-3.0**, which is worth a legal confirmation for the hosted tier.
- Distribution is undecided: `packages/*` are `private` and unpublished, and the OCaml packages likewise. "Free self-host" needs an answer for how people obtain it.
