`sol-svc`: make the JWKS refresh single-flight and Eio-safe, and turn every exception outside the handler into a counted 500

**Depends on:** None.

**Finding:** FND-0050 (`internal/pipeline/audits/findings/`).

**Premise verified 2026-09-24** against `origin/main @ fd5c7e0c`, behaviourally: two
concurrent validations with a yielding fetch give
`Sys_error("Mutex.lock: Resource deadlock avoided")` on the second, and cohttp-eio
answers a raising callback with an empty reply.

## Problem

`get_jwks` (`auth_internal.ml:182-198`) holds a `Stdlib.Mutex` across the HTTPS fetch.
A second request fiber that misses the cache while the first is fetching raises
`Sys_error` from `Mutex.protect`. `dispatch` runs authentication outside the handler's
`try` (`service.ml:145-173`), so the exception reaches cohttp-eio. The client gets
no HTTP response, and no metric is recorded. This happens at startup and every 300 s
under concurrent load, for every `Jwks_url` service. Separately, a token signed with a
newly rotated key (unknown `kid`) is rejected until the TTL expires.

## Remediation

1. Replace the `Stdlib.Mutex` in `get_jwks` with a single-flight refresh that
   concurrent misses await: an `Eio.Mutex`, or a shared `Eio.Promise` for the refresh
   in flight. Keep `validate` Eio-agnostic apart from what the injected fetch needs.
2. On an unknown `kid` with a fresh cache, refetch once, rate-limited (at most once
   per 30 s), before rejecting.
3. Widen `dispatch`'s boundary: any exception other than cancellation and fatal ones,
   raised during authentication, body reading or the handler, becomes
   `Response.internal_error` and is logged, so the request gets a 500 and is counted.

## Acceptance criteria

- Test: two concurrent validations against a fetch that yields both succeed, with
  exactly one fetch.
- Test: an unknown `kid` triggers one refetch and succeeds when the new JWKS has it.
- Test: an exception raised in authentication yields a 500 response through `dispatch`.
- Mutation check: restoring `Stdlib.Mutex` fails the concurrency test.
- Demo/example: state applicability in completion notes.
- TS parity: record the `@sol-fab` JWKS verdict (DEC-022).

## Completion notes (2026-09-24)

Premise re-checked on the audit branch (`fd5c7e0c` + the audit commit): `get_jwks` still
held `Mutex.protect jwks_cache_mutex` across the fetch. A second real trigger for the
same boundary gap turned up while testing: an unverified token whose payload is the
JSON array `[]` made `Yojson.Safe.Util.member` raise inside authentication. Against a
live service, the client saw `connection closed by peer`.

- `get_jwks` refreshes under an `Eio.Mutex` (`use_ro`, so a cancelled or failed fetch
  releases rather than poisons it) and rechecks the cache after acquiring it. Concurrent
  misses wait for one fetch.
- An unknown `kid` refetches once, reusing any set fetched in the last 30 s, then
  rejects.
- JWT claims must be a JSON object (unverified and verified paths); otherwise 401.
- `Service.dispatch` is wrapped in `respond_or_500`: any exception other than
  cancellation and fatal ones becomes a logged 500, so every request gets a response
  and is counted. It is exposed as `Service.For_testing.respond_or_500`.
- Tests: two concurrent validations with a yielding fetch both verify, with one fetch.
  An unknown `kid` refetches (cache seeded 60 s old) and is rate-limited (seeded 5 s
  old, no fetch). A non-object payload gets 401 through the validator and through a
  live service. An exception inside the boundary becomes 500.
- Mutation checks (each built and failed only its intended test): restoring
  `Stdlib.Mutex`/`Mutex.protect`, a refetch that returns the stale set, no refetch rate
  limit, no object check, and a boundary that re-raises. Two earlier mutants that did
  not compile were discarded and replaced by these.
- `sol-svc.md` describes the single-flight refresh, the `kid` refetch, the non-object
  401 and the widened boundary, and drops the "JWKS refresh on an unknown `kid`" entry
  from Out of Scope. `check_framework_doc_signatures.sh` passes.
- **Demo/example:** not applicable. No author-facing API change (the `For_testing`
  addition is test-only); examples configure JWT the same way.
- **Language parity:** not applicable. The TypeScript `svc` package does not own auth
  (`sol-typescript/packages/svc/src/index.ts:41`: routing and auth stay with the
  application), so there is no `@sol-fab` JWKS cache to diverge.

**Review round 2 (2026-09-24):**

- A failed fetch is remembered for 5 s and returned to every waiter.
  Previously each request queued on the mutex ran its own fetch in turn during an
  IdP outage (5 concurrent validations made 5 fetches), so the Nth waited N timeouts.
- An unknown `kid` whose refetch fails or is rate-limited is a 401, not a 500. The
  cached set is authoritative within its TTL, so made-up `kid`s cannot produce 5xx
  on demand.
- The `dispatch` boundary now has its own test: `Service.For_testing.dispatch` with
  a `fetch_jwks` that raises gets a 500. Earlier, the only live-service trigger (a
  non-object payload) had become a 401 and no longer reached it.
- Mutation checks (each built and failed only its test): `dispatch` without the
  boundary, no failure sharing, and a failed refetch reported as 500.
