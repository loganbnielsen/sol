**Depends on:** None.

## Problem

`@sol-fab/kafka@0.5.1` declares `"@sol-fab/obs": "^0.1.0"`, which resolves to
`0.1.2`. `@sol-fab/obs` moved to `0.4.0` with `OBS-051` (the injection-aware
workload-identity reader). Any consumer that depends on both — and
`examples/pluto/app/demo_ts` does, after `OBS-051` — resolves **two** copies: its
own `0.4.0` for `makeLokiPusher`/`resourceAttributes`, and `0.1.2` for the
`traceparentOf`/`extractTraceparent` that `@sol-fab/kafka` re-exports.

Reproduced on `main` before the fix:

```console
$ cd examples/pluto/app/demo_ts
$ npm ls @sol-fab/obs
demo-ts@ /home/lbendtly/Code/sol/examples/pluto/app/demo_ts
├─┬ @demo-ts/contract@ -> ./contract
│ └─┬ @sol-fab/kafka@0.5.1
│   └── @sol-fab/obs@0.1.2
├─┬ fulfillment-worker@ -> ./fulfillment_worker
│ └── @sol-fab/obs@0.4.0
└─┬ order-svc@ -> ./order_svc
  └── @sol-fab/obs@0.4.0
```

Nothing misbehaves today: `traceparentOf`/`extractTraceparent` are unchanged
between `0.1.2` and `0.4.0`. But this is a second copy of a package whose whole
purpose is to be the single shared vocabulary (DEC-022), and the next `obs` move
would leave an app's re-exported tracing and its own `@sol-fab/obs` as two
implementations of one contract — silently, because both compile.

## Remediation

- [x] `@sol-fab/kafka` widens its dependency to `@sol-fab/obs@^0.4.0` and
      releases `0.5.2` through the tag-driven OIDC/`provenance` workflow.
- [x] The FEAT-084 TypeScript templates (`platform/shared/templates/{svc,worker}-ts`)
      move from `@sol-fab/obs@^0.3.0` to `^0.4.0`, so a scaffolded unit is
      identity-aware instead of pinned below the identity reader.
- [x] `examples/pluto/app/demo_ts` refreshes its lockfile and resolves a single
      `@sol-fab/obs@0.4.0`.
- [x] `internal/ci/check_platform_component_drift.py` asserts the demo lockfile
      resolves exactly one `@sol-fab/obs` at or above the identity floor, and
      applies its obs-floor check to the template packages as well as the demo.

## Acceptance criteria

- `npm ls @sol-fab/obs` in `examples/pluto/app/demo_ts` reports exactly one
  version, `>= 0.4.0`.
- The TypeScript golden-path smoke still passes, so the `OBS-051` log/trace
  identity behavior is intact.
- The guard fails when a second `@sol-fab/obs` version reappears in the lockfile
  or when a template falls below the identity floor.

## Completion (2026-10-03)

**Package.** `@sol-fab/kafka@0.5.2`
([`loganbnielsen/sol-kafka#11`](https://github.com/loganbnielsen/sol-kafka/pull/11),
tag `v0.5.2`) now depends on `@sol-fab/obs@^0.4.0`; the published tarball's
dependency was read back from the registry to confirm it. The package's only obs
use is `extractTraceparent` plus the re-export of `traceparentOf`/
`extractTraceparent`, both unchanged across the jump, so no code changed and
`0.5.2` is a patch. 59 of its 60 tests pass (the broker-backed partitioning test
self-skips without a broker).

**Consumers.** All three `examples/pluto/app/demo_ts` packages and both FEAT-084
templates move to `@sol-fab/kafka@^0.5.2` and `@sol-fab/obs@^0.4.0`, naming the
floor that carries the fix rather than one range that still admits the
two-copy `0.5.1`.

**Verification.**

```console
$ cd examples/pluto/app/demo_ts && npm ls @sol-fab/obs
├─┬ @demo-ts/contract@ -> ./contract
│ └─┬ @sol-fab/kafka@0.5.2
│   └── @sol-fab/obs@0.4.0 deduped
├─┬ fulfillment-worker@ -> ./fulfillment_worker
│   └── @sol-fab/obs@0.4.0
└─┬ order-svc@ -> ./order_svc
  └── @sol-fab/obs@0.4.0 deduped
```

One version, deduped. The demo builds and its 5 tests pass (real Postgres), so
the `OBS-051` identity path is unchanged: the identity comes from
`makeLokiPusher`/`resourceAttributes`, which this dependency never touched. Both
templates were scaffolded into a scratch tree and typechecked on a single
`@sol-fab/obs@0.4.0` (`worker-ts` shows kafka's obs deduped to the same copy).

**Guard.** `check_platform_component_drift.py` now also parses the demo lockfile
and fails when it resolves anything other than one `@sol-fab/obs` at or above the
identity floor, and applies the floor check to the two template packages. Two
mutations were added (`downgrade_ts_template_obs_pin`,
`duplicate_obs_in_demo_lockfile`); the guard and all 19 mutation cases pass. The
live confirmation is the TypeScript golden-path smoke on this PR's head, which
deploys the demo to a real cluster and asserts its trace identity.
