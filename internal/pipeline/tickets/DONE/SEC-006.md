Refuse `Unverified_dev_only` JWT auth at runtime unless explicitly opted in

**Depends on:** None.

**Finding:** FND-0037 (`internal/pipeline/audits/findings/`).

**Premise verified 2026-09-23** against `origin/main @ f3e9480b` while filing (see the finding).

## Problem

`Unverified_dev_only` trusts unsigned tokens and nothing prevents it from running in production; the name is the only guard.

## Remediation

In `Service.Make.run`, return `Error (`Config …)` if any route (or `metrics_auth`) uses `Unverified_dev_only` and `SOL_ALLOW_UNVERIFIED_JWT` is not `1`. `sol local up` renders that variable; `sol deploy` never does, so a profile target cannot run it. Document in `sol-svc.md` (coordinate with DOCS-021).

## Acceptance criteria

- Test: route with `Unverified_dev_only`, env unset → `run` returns `Error (`Config _)`; env `1` → runs.
- Local manifests render the opt-in; deploy manifests do not (render test).
- Demo/example: any example using the mode runs under `sol local up` — note in completion notes.
- TS parity: record verdict for TS svc auth.

## Completion notes

- `Service.Make.run` returns `Error (`Config ...)` before binding when any route, or
  `metrics_auth`, uses `` `Jwt { verification = Unverified_dev_only; _ } `` and
  `SOL_ALLOW_UNVERIFIED_JWT` is not `1`. The message names the variable and points at
  `Verified_signature_required`.
- `Sol_cli_executor.local_development_spec` adds `SOL_ALLOW_UNVERIFIED_JWT=1` to a spec's
  config. Only `Sol_cli_executor.local` (the `sol up` local-cluster path) applies it;
  `sol deploy` and `--emit-to` render without it.
- Tests: `sol-svc` `test_service.ml` checks that without the opt-in a route with
  `Unverified_dev_only` and a `metrics_auth` with it are each a startup `Config` error.
  Those cases use a pre-resolved `stop`, so a missing guard fails fast instead of
  hanging. The test binary opts in globally for its other (dev) cases. CLI
  `test_manifest_render.ml`: a local render carries the opt-in; a deploy render does not.
- Mutation check (`audits/README.md`): replacing the guard call with
  `ignore refuse_unverified_jwt` builds (rc=0) and fails both `sol-svc` guard tests.
- Spec: `sol-svc.md`'s warning now describes the guard (the DOCS-021 text said "SEC-006
  adds that guard").
- Demo/example: no example uses `Unverified_dev_only`
  (`rg -n Unverified_dev_only examples internal/fixtures` is empty); `sol up` renders the
  opt-in, so local development with the mode keeps working.
- Language parity: the TS svc (`@sol-fab/*`, outside this repo) is unassessed here;
  whether it has an equivalent dev-only JWT mode needs checking in that repo.
