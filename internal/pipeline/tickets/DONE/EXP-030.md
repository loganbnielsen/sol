`sol logs` still fails for `fn` (CronJob) services (EXP-024 fix reverted, never refixed)

**Description:** `cmd_logs.ml` labels fn services `"cronjob"` internally (line 65) but its actual log-source lookup only branches `Svc | Worker -> Deployment k8s_name` (line 83) — there is no CronJob/Job-pod branch, so `sol logs <fn-service>` has no code path that succeeds. This is the original EXP-024 finding. That fix was merged (`0db7fa38`) then reverted the same day (`517f0ca5`, "Revert 'Merge branch 'EXP-024/logs-fn-cronjob'''") after a test failure (`cdb071a9`, "pipeline: test failure blocked EXP-024"), and was never refixed — the ticket still sits in `project/tickets/DONE/EXP-024.md` describing a fix that no longer exists in `main`.

**Impact:** An engineer who deploys a scheduled function and runs the documented `sol logs <service>` gets an unconditional failure ("Service not found in namespace…") with no guidance toward the CronJob-specific workaround, contradicting the platform's promise of kubectl-free day-2 operations.

**Remediation:** Add a CronJob-aware branch to `cmd_logs.ml`/`sol_cli_logs.ml`: when the service type is `Fn`, find the most recent Job pod for the CronJob (e.g. `kubectl get pods -n <ns> -l job-name=<name> --sort-by=.status.startTime`) and tail its logs, or at minimum print an actionable message pointing at the manual `kubectl logs job/<name>-<hash>` equivalent. Before merging, run the full test suite locally first — the original fix's test failure was never diagnosed.
