`sol.toml` must reject unknown keys and tables, as `sol.yml` already does

**Depends on:** None.

**Finding:** FND-0033 (`internal/pipeline/audits/findings/`).

**Premise verified 2026-09-23** against `origin/main @ f3e9480b` while filing (see the finding for the command/probe and observed output).

## Problem

`Sol_cli_toml.load_result` reads known paths only; `[infra.scale] replica = 3`, `[infra.sacle]`, `[infra.rolout]` all load as `Ok` with the setting dropped (probe in FND-0033). The "forward-compatible" rationale is void under the pre-alpha no-compat policy, and `sol.yml` is already fail-loud (FEAT-025/028).

## Remediation

After reading known keys, walk the document and reject any key/table not in the schema for its section, naming key and file.

## Acceptance criteria

- Each typo case from FND-0033 returns `Error` naming the unknown key and the file.
- Every scaffolded `sol.toml` (all templates in `sol_cli_scaffold_templates.ml`) and every `sol.toml` under `examples/` and `internal/fixtures/` still loads.
- Demo/example: examples must still load; state that in completion notes.
- TS parity: `sol.toml` is language-neutral CLI config — no language-parity impact.

## Completion notes

- `Sol_cli_toml.load_result` checks the document against an explicit schema
  (`key_schema`) before reading values: `[infra.scale]`, `[infra.env]`,
  `[infra.volumes.<name>]` fields, `[infra.deploy]`, `[infra.labels]`,
  `[infra.rollout]` including canary step tables (`weight`, `pause.duration`), and
  `[service]`. User-data tables (`config`, `extra_labels`, volume names) are not
  checked. An unknown key is a `Validation` error that names the key, the table, and
  the keys Sol reads there.
- Event `sol.toml` files: `Sol_cli_workspace_scan.topics_of_toml`/`discover_topics`
  used to turn *any* load error into "no topics". That would have silently swallowed
  the new error (a misspelled `topic =` drops the topic from the deploy). They now
  return the error, and the plan surfaces it as `Toml_error`. A missing file still
  declares nothing.
- Tests: new `cli/sol/test/test_toml_keys.ml` (8 rejections naming the key; the
  every-documented-key document, empty file, and the three scaffold templates load)
  and a misspelled-event case in `test_deployment_plan.ml`. All six `sol.toml` files
  under `examples/` and `internal/fixtures/` load (one-off probe, not committed).
- Mutation checks (`audits/README.md`), builds rc=0: disabling `check_known_keys`
  fails all 8 rejection tests; restoring `Error _ -> Ok []` in `topics_of_toml` fails
  "misspelled event sol.toml is an error".
- Docs: `docs/deployment/escape-hatches.md` says the table is the whole schema and that
  unknown keys are errors.
- Observed, not changed: `discover_topics` still skips an invalid topic *name* with a
  printed warning (`filter_validated`), rather than failing. That is outside this
  ticket; it is visible, unlike the case fixed here.
- Demo/example: example and fixture `sol.toml` files are unchanged and verified to load;
  the scaffold templates are covered by tests.
- Language parity: no language-parity impact (`sol.toml` is read by the CLI for both
  languages; the TypeScript demo's `sol.toml` files load).
