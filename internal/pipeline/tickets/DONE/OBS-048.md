Decouple application latency from the log and trace backends: keep a stdout copy when `LOKI_URL` is set, and export asynchronously

**Depends on:** None.

**Finding:** FND-0051 (`internal/pipeline/audits/findings/`).

**Premise verified 2026-09-24** against `origin/main @ fd5c7e0c`: against a Loki that
accepts TCP and never answers, `Sol_obs.log_info` returned after 5.00 s, and the line's
content appeared nowhere.

## Problem

`Obs_loki` and `Obs_tempo` push each closed span or log line inline, in the calling
fiber, with a 5 s timeout. A failed push is reported to stderr without the line's
content. `Sol_obs.of_env` makes Loki the *only* log backend when `LOKI_URL` is set, and
rendered manifests always set it. So a slow Loki adds up to 5 s (10 s with Tempo) to
every log call in request and message handlers, and a Loki outage drops every
application log line, including the ones that would explain it.

## Remediation

1. This repository (`framework/ocaml/sol-obs/lib/sol_obs.ml`): when `LOKI_URL` is set,
   compose Loki *with* the stdout backend rather than instead of it.
2. obs-loki-eio and obs-tempo-eio (own repositories, re-pinned here): export through a
   bounded in-memory queue drained by a background fiber. Batch per push, drop the
   oldest on overflow, count dropped lines/spans on a metric, and print a
   rate-limited stderr summary. `emit_span` returns without network I/O. The queue's
   fiber needs a switch, so `create` takes `~sw`. Update `Sol_obs.of_env` and its
   callers.

## Acceptance criteria

- Test: with `LOKI_URL` set, a log line appears on stdout.
- Test: against a black-holed endpoint, a log call returns in well under 1 s, and the
  drop counter increases once the queue is full.
- Demo/example: the local demo still shows logs in Grafana; state it in completion notes.
- TS parity: `@sol-fab/obs`'s pusher is asynchronous (`fetch` without await), but see
  BUG-037; record the verdict (DEC-022).

## Progress

**Part A (2026-09-24), this repository: done.** `Sol_obs.of_env` composes a spans-only
stdout backend with Loki when `LOKI_URL` is set, stdout first. Log lines reach
`kubectl logs` and survive a Loki outage; metric increments are not echoed. Test:
with `LOKI_URL` set, a log line is on stdout, is still pushed to Loki, and no `METRIC`
line appears. Mutation checks (each built and failed that test): stdout spans
silenced, and metrics echoed. Demo: the local demo's workers now print their log lines
as well as pushing them; nothing to change. Parity: `@sol-fab/obs` has the same log-loss
gap. With `LOKI_URL` set, `makeLokiPusher` (sol-obs `src/loki.ts:16-44`) only `fetch`es
and never writes to the console. Its push is not awaited, so it has no latency
coupling. Tracked as FEAT-099.

**Part B, still open:** asynchronous, bounded export in obs-loki-eio and obs-tempo-eio
(remediation item 2). Part A removes the log loss but not the latency: a slow Loki
still blocks each log call for up to 5 s.

## Completion notes (2026-09-24)

**Part B, done.** obs-loki-eio #15 (`148a9706`) and obs-tempo-eio #2 (`e117aece`),
both released as 0.2.0, export asynchronously. `emit_span` only enqueues, and a
background fiber on the caller's switch pushes batches. The queue is bounded and drops
the oldest (counted); failures go to rate-limited stderr; `flush ?timeout` is a hard
bound. The libraries' tests cover: emit does not wait for a black-holed backend,
overflow drops the oldest, flush delivers, and flush's timeout is a hard bound.
Mutation checks: synchronous emit, unbounded queue, no-op flush, no `with_timeout`.
Reviewed twice.

In Sol: `Sol_obs.of_env ~sw` and `Sol_obs.flush`. The `Service`, `Worker`, `Sol_jobs`
and `Fn` runtimes flush when `run` returns; a Lambda `-fn` flushes after every
invocation, because a frozen sandbox cannot run the export fiber. The CLI's deploy-event
push flushes before its `Eio_main.run` ends. All call sites (examples, fixtures,
scaffold templates, tests, specs, tutorial) pass a switch. Pins are bumped to 0.2.0 in
`sol-obs.opam`, `examples/pluto/pluto.opam`, `internal/fixtures/venus/venus.opam` and
the scaffold template. Test: `Sol_obs.flush` delivers a queued line before returning
(mutation: a no-op flush fails it).

- **Sequencing:** CI resolves every support package at its `main` HEAD
  (`internal/ci/resolve-support-packages.sh`), so the library merges broke CI for any
  open Sol PR until this one landed. They were merged with no Sol PR open, and this PR
  immediately after.
- **Demo/example:** the pluto example mains, the venus fixtures, the local demo and
  the scaffolded mains all open a switch for `Sol_obs.of_env`. The retry demo and the
  local demo push to Loki as before.
- **Language parity:** `@sol-fab/obs`'s push is already fire-and-forget (not
  awaited), so this latency fix is equivalent. The stdout copy (part A) is not
  equivalent: FEAT-099.
