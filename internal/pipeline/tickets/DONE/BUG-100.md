Remove sol secret's --env axis, which selects nothing and rejects the documented rotation command

**Depends on:** None.

**Premise verified (2026-09-29):** At `origin/main` `7f6aa377`, `cli/lib/deploy/sol_cli_secret.ml:14-25` `mode_of_env` accepts only hosted, local and cloud spellings. `Local` and `Customer_cloud` behave identically in `validate_operation_context` (`:218-224`). The cluster written to comes solely from `--target` (`cli/bin/cmd_secret.ml`, `Cmd_destination.remote`). `cli/test/test_secret.ml:38-55` asserts that `dev` and `staging` are rejected.

**Premise reverified (2026-09-29):** At `origin/main` `bdc5d10b`, `cmd_secret.ml` still requires `--env` and `Sol_cli_secret` still parses only mode aliases, independent of the resolved target context.

## Problem

`sol secret set|list|delete` requires `--env`, but that flag addresses nothing:

- **The documented rotation command fails.** `docs/deployment/credential-rotation.md:44` gives `sol secret set --env prod --target prod/aws/us-east-1 DATABASE_URL`. `prod` is rejected as an `unknown secret environment`, so the runbook command does not run.
- **The help text is wrong.** It says "local/dev use the local Kubernetes path … other names use the customer-cloud Kubernetes path". `dev` and every other name are rejected, and `local` does not select the local cluster.
- **The flag can mislead about the destination.** `--env local --target prod/aws/us-east-1` writes production Secrets and restarts production workloads while saying `local`. `ROADMAP.md:177` also shows `sol secret set DATABASE_URL --env local` with no target, which cannot run because `--target` is required and there is no `sol local secret` form.

This is a second addressing axis on a target-primary command, which DEC-031's axis rule excludes. The only real behavior behind it is the hosted stub.

## Remediation

Address secrets by target alone. Drop `--env`, and derive the hosted/customer-cloud mode from the resolved destination if the hosted stub still needs one. Add a `sol local secret set|list|delete` form, consistent with the other `sol local <command>` forms. Update the docs that show `--env`.

## Acceptance criteria

- The rotation command in `credential-rotation.md` runs as documented against a configured target.
- No flag value can claim one environment while writing another.
- `sol local secret set|list|delete` works against the local cluster, and the `ROADMAP.md`/`substrate.md` examples use it and run.
- CLI tests cover the new argument surface. No application-language parity impact (CLI-only).

## Completion notes

- Removed the `--env` parser and mode routing. `sol secret` resolves the configured `--target`, and `sol local secret` uses the local context for set/list/delete. The unreachable hosted stub and alias parser are retired.
- Updated the rotation, tutorial, roadmap, and substrate examples. Focused CLI command-surface and secret read tests pass. The full `dune test cli/ --force` run hit unrelated scaffold build failures from missing framework libraries in generated workspaces.
- No application-language parity impact: secret destination selection is CLI-only.
