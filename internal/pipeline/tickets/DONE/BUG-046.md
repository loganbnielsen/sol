`sol-svc`: deliver an external `stop` to the server, and reject a malformed `PORT`

**Depends on:** None.

**Finding:** FND-0041 (`internal/pipeline/audits/findings/`).

**Premise verified 2026-09-23** against `origin/main @ f3e9480b` while filing (see the finding for the command/probe and observed output).

## Problem

`Service.Make.run` passes only the signal promise to `Cohttp_eio.Server.run ~stop`; an external `?stop` keeps the server accepting for the full `drain_timeout_s`, then reports "drain timeout reached" (observed: 3.00s with nothing in flight). A non-integer `PORT` silently falls back to the default (observed with `80800x`, `tcp://…`).

## Remediation

Resolve the server's stop from either signal or external stop; return `Error (`Config …)` for an unparsable `PORT`. The preStop/readiness-flip gap (FND-0041 c) is out of scope here.

## Acceptance criteria

- With `~drain_timeout_s:3.0` and an external stop resolved at listen, `run` returns well under 3s without the drain-timeout message (test uses a non-trivial timeout, not 0.1).
- `PORT=abc` makes `run` return `Error (`Config _)` naming the value.
- TS parity: check the TS svc shutdown/PORT handling and record a verdict.
- Demo/example: not applicable — state in completion notes.

## Completion notes

- **External stop:** `Service.Make.run` now resolves a `server_stop` promise from either
  the signal or the caller's `?stop`, and passes that to `Cohttp_eio.Server.run ~stop`.
  An external stop therefore stops accepting immediately and returns once connections
  drain; the drain timer only fires for work that outlives `drain_timeout_s`.
- **PORT:** a set, non-empty `PORT` that is not an integer in 0-65535 is
  `Error (`Config "PORT=\"...\" is not a port number (0-65535)")`. An empty `PORT` counts
  as unset, like every other variable `run` reads.
- Tests (`framework/ocaml/sol-svc/test/test_service.ml`): with `~drain_timeout_s:3.0`
  and nothing in flight, an external stop returns in under 1.5s (the audit probe measured
  3.00s before the fix); `PORT=80800x` is a `Config` error naming the value.
- Mutation checks (`audits/README.md`), builds rc=0: pointing the server back at
  `signal_stop` only fails "external stop does not wait out the drain window"; a
  fall-back arm for malformed PORT fails "malformed PORT is a startup Config error".
- Spec: `sol-svc.md` states the PORT rule in the `run` signature and the resolution
  order.
- Demo/example: not applicable (no author-facing API change; a malformed PORT now fails
  at startup rather than listening elsewhere).
- Language parity: FEAT-082's TS golden path uses `@sol-fab` packages outside this repo,
  so the TS svc's PORT/stop behaviour is unassessed here and recorded as such (not
  "equivalent").
