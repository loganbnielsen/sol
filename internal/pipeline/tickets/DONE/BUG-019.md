**Depends on:** None.

The commit-time perf status output prints a `jq` error — `Cannot iterate over null (null)` — even though the commit succeeds.

## Problem

After the pre-commit hook runs the test suites and the post-commit/perf status code prints the summary table, output ends with an unhandled jq error similar to:

```
jq: error (at .../devtools/perf/perf_baseline.json:8720): Cannot iterate over null (null)
```

The commit itself completes successfully, so this is not currently blocking, but it is noisy and may indicate a real data-shape assumption in the perf summary tooling (e.g. a missing/null history array for a suite).

## Goal

Commit output should end cleanly after the perf summary. If the baseline file has an unexpected shape, the tooling should handle it gracefully or print a useful message — not an uncaught jq error.

## Remediation

- Reproduce by running a normal `git commit` that triggers the test suites (broker up so the kafka suite runs).
- Find the jq invocation producing the error (likely in `devtools/hooks/post-commit` → `cli/platform/local/scripts/perf.sh` or `run_tests.sh`'s summary path).
- Harden the query so a missing/null `history` array is handled (e.g. `// []` or an explicit check), or fix the writer if it is emitting malformed baseline data.
- Verify the commit output is clean after the fix.

## Acceptance criteria

- A normal code commit with the kafka suite enabled produces no jq error after the perf summary.
- A deliberately malformed/empty baseline section does not crash the perf status output.
