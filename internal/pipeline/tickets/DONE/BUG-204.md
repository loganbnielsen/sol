**Depends on:** None.

**Premise (verified 2026-10-04 at `origin/main @ f4284422`):** holds.
`.github/workflows/release.yml` publishes the GitHub release with
`gh release create … --generate-notes`, whose body GitHub generates from every merged pull
request since the previous release, and its "Publish the migration runner, once" step fails
when the version's image already exists.

## Problem

Two defects, both exposed by cutting `v0.1.0-alpha.7`.

**1. The release body is unbounded, and the API rejects it.** The first run reached the last
step and failed there:

```console
$ gh run view --job 37210258576 --log-failed
release	Publish the GitHub release	HTTP 422: Validation Failed (https://api.github.com/repos/loganbnielsen/sol/releases)
release	Publish the GitHub release	body is too long (maximum is 125000 characters)
release	Publish the GitHub release	##[error]Process completed with exit code 1.
```

Everything before it succeeded: the release binary, `ghcr.io/loganbnielsen/sol-migration-runner:v0.1.0-alpha.7`,
the bundle, and the installed-release smoke. The campaign's range since `v0.1.0-alpha.6`
(2026-06-11) is large enough that the generated body cannot fit, so the release was never
published and no user could retrieve the archive.

**2. A publish that fails after the image is pushed cannot be resumed.** The runner step
refused to continue once the image existed:

```console
$ git show f4284422:.github/workflows/release.yml | sed -n '/Publish the migration runner/,/push/p'
          if docker manifest inspect "$RUNNER_REPO:$VERSION" >/dev/null 2>&1; then
            echo "::error::$RUNNER_REPO:$VERSION already exists; a release version is published once"
            exit 1
          fi
```

That guard is right about what it protects — a released version's artifacts must not move —
but its consequence is that any failure after the push leaves the version un-publishable
without superseding it. Nothing user-visible had been published here: the failure was in the
step after the image, so the version was burned for no reason.

## Remediation

`.github/workflows/release.yml`:

1. **Bound the body.** Generate the changelog through the API, keep the first 100000
   characters up to a line boundary (the API counts characters, so a line boundary is safe
   for a multibyte body), and append a pointer to the full compare range when anything is
   dropped. A changelog that fits is carried whole.
2. **Make the runner publish idempotent.** `docker pull` the version's tag: if it is already
   published, reuse its digest instead of overwriting (or refusing) it. The digest is what
   Sol consumes and cannot move once pushed (SEC-011), so the invariant holds.
3. **Keep "published once".** A version refuses to publish once its GitHub *release* exists;
   the digest reuse only ever completes an interrupted publish. The release, not the image,
   is the publication marker.
4. **Add `workflow_dispatch` with a `version` input.** The workflow definition comes from the
   default branch, so a recovery can run against an existing tag without moving it; the
   artifact is still built from the tag's tree, and the step refuses a `version` that is not
   a tag, or whose commit is not the checkout.

## Acceptance criteria

- The publish step's script, run with a stubbed `gh` against a 379686-character generated
  changelog, produces a body of 100297 characters carrying the release revision, the runner
  digest and the compare pointer; a 1899-character changelog is carried whole.
- `v0.1.0-alpha.7` is published from the tag's revision by resuming the workflow, with the
  runner digest of the first run, and the downloaded archive passes the installed-release
  smoke and the clean-user qualification.
- A second run for the published version is refused, naming the version.
- Language parity: no application-facing contract change; the release carries the
  language-neutral CLI and platform (DEC-022).

## Completion notes

Both defects are fixed in `.github/workflows/release.yml`. Offline verification (a session
harness that parses the workflow with PyYAML, substitutes the step's expressions, and runs
the step against a stubbed `gh`): all eleven `run:` blocks parse under `bash -n`; the
oversized case produced a 100297-character body from a 379686-character changelog, warned,
kept the generated prefix, and appended the compare pointer; the small case passed through
unchanged. The authoritative verification is the resumed run against
`v0.1.0-alpha.7` — recorded in `RELEASE-006` and the run record when it lands.
