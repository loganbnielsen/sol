Keep retry and DLQ topics isolated by the original consumer group

**Depends on:** None.

**Premise verified (2026-09-28):** Traced `framework/ocaml/kafka-eio-service/lib/kafka_service_retry_topics.ml:180-202,432-440` and representative callers/tests at origin/main `6eb36b2c`. The audit records reproduced behavior, positive controls and practical limits.

## Problem

Short group IDs pay.ments, pay_ments and pay-ments all produce orders.pay-ments.retry and the same DLQ. Relay consumers retain distinct original group IDs plus -sol-retry, so each independent group consumes the others' retry records. This mixes business handlers and creates duplicate or wrong-group effects. The source identity can be ordinary framework-generated dotted consumer groups.

## Remediation

Derive bounded relay topic names from a collision-resistant representation of the original group ID, including short IDs whose punctuation is normalized. Apply the same rule to retry and DLQ. Update affected callers/fixtures together; do not add compatibility aliases for the unreleased API.

## Acceptance criteria

- Punctuation variants, empty/unscoped and long IDs have distinct bounded retry/DLQ names. Two groups on one source cannot consume one another's retries; publication-before-ack and intended within-group sharing remain intact. Update a runnable retry example and record the OCaml/TypeScript naming-convention verdict.
- Completion notes identify runnable example/demo coverage and the per-language capability verdict, or explain why either is not applicable.

## Completion (2026-09-29)

- **Premise re-verified** at origin/main `788e688d`: `canonical_group_segment` mapped `.`/`_`/other punctuation to `-` and only added a hash for overlong ids, so `pay.ments`, `pay_ments` and `pay-ments` all produced `<source>.pay-ments.retry` and the same DLQ. The retry relay consumer group (`<group_id>-sol-retry`) stayed distinct, so two groups could each consume the other's retry records.
- **Fix.** `canonical_group_segment` now always appends a 12-hex-digit hash of the **original** `group_id` to the sanitized readable prefix, truncating the prefix so the segment stays ≤ 64 bytes. The same `relay_topic_name` builds both the retry and DLQ names, so both are collision-resistant; a given `group_id` still maps deterministically to one name (within-group sharing and publication-before-ack are untouched, and no caller or fixture change was needed — the unreleased API takes no compatibility alias).
- **Tests** (`framework/ocaml/kafka-eio-service/test/test_kafka_service.ml`, `retry_topics` group): the existing scope/sanitize/unscoped/overlong cases now assert the readable prefix plus the computed hash; a new case proves `pay.ments`/`pay_ments`/`pay-ments` yield three distinct retry names, each deterministic, and that the readable prefix survives; the overlong case also asserts the 64-byte segment bound. **Mutation-checked**: emptying the hash makes the punctuation-variant case fail while the fix passes. All 41 unit tests pass; the broker-backed `test_kafka_service_integration.ml` (which derives its topic names from the same function) still compiles.
- **Docs / naming convention.** `framework/ocaml/kafka-eio-service/kafka-eio-service.md` and the cross-language `internal/specs/framework-conventions.md` retry/DLQ row now state the sanitized-prefix-plus-hash segment and the punctuation-variant guarantee.
- Validation: full `dune build`; `dune fmt --preview` clean; no-comments policy holds.
- **Runnable example**: there is no `examples/` durable-retry walkthrough; the runnable coverage is the broker-backed `test_kafka_service_integration.ml` retry/DLQ cases, which compute names through the changed function and therefore exercise the new scheme unchanged. **Naming-convention parity verdict (DEC-022)**: this is a shared convention, recorded language-neutrally in `framework-conventions.md`; the TypeScript implementation lives in the external `@sol-fab/kafka` package (`loganbnielsen/sol-kafka`), which must adopt the same hash-suffixed segment — no TypeScript retry/DLQ naming code exists in this repository to change here.
