## The question

Run 8's §B B3 requires driving a transaction against an application's private
`ClusterIP` service. No identity the platform provisions can do that:

| Principal | platform namespaces | application namespaces |
|---|---|---|
| `cluster-access` | `*.* [*]` | **no access at all** |
| `deploy` | — | read-only on workloads; no `portforward`, no `exec` |
| `operator` | — | read-only diagnostics; no `portforward` (deliberate) |
| `provisioner` | no access entry exists | — |
| cluster administrator | `Unauthorized` (no creator-admin) | — |

The tempting fix is to grant `pods/portforward` to operator or deploy. That would be
wrong: **no production identity should be able to tunnel into arbitrary application
pods**, and the fact that none can is a property worth keeping. The thing that is
wrong is the *procedure*, which assumes it can invoke a private service without
saying how the harness obtains connectivity.

## Decision (2026-09-21)

### 1. The production identity model is unchanged

provisioner = infrastructure mutation · publisher = artifact publication ·
deploy = application/release mutation · operator = observation and diagnosis. No
verb is added to any of them for the convenience of a test.

### 2. A qualification-only transport capability

A distinct Kubernetes group (`sol:qualifiers`) and an IAM principal for the
qualification harness, granting **only** what is needed to address and open a
transport to a target:

| Resource | Verbs | Why |
|---|---|---|
| `pods`, `services` | `get`, `list` | resolving a service's selector to a pod — addressing, not observation |
| `pods/portforward` | `create` | the transport itself |

Deliberately absent: any mutating verb, `pods/exec`, `pods/log`, `events`,
`secrets`. Diagnosis stays the operator's; the qualifier carries traffic and
nothing else.

### 3. It is not production infrastructure

The capability is established by the qualification harness, **never** by
`sol cloud apply` and never from a production Terraform root. A customer
environment must not be able to acquire it by running Sol's normal lifecycle, and
no target field names the qualifier principal. A guard
(`internal/ci/check_qualification_transport.sh`) asserts both directions: the
production roots never reference the qualifier group, and the transport manifest
carries no verb beyond the table above.

### 4. Evidence discipline

The qualification record must state which identity established transport,
separately from the identities whose contracts are being qualified. Transport is
harness mechanics; the reads and mutations under test belong to the production
identities. Using a harness capability is not cheating as long as it is never
presented as evidence about a production identity.

### 5. Broker progress is not application evidence

A conforming Kafka record can be consumed and still fail application handling —
demonstrated live: a malformed record was skipped
(`DECODE_ERROR skip=true error="wire format: invalid magic byte"`) while the
consumer group's committed offset advanced. So `CURRENT-OFFSET == LOG-END-OFFSET`
establishes **transport**, not processing. A qualification row that asserts an
application effect must show the effect: downstream state, an application-level
record, or the application's own log line.
