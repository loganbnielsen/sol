Make Kafka transport security an explicit, rendered posture instead of an implicit Plaintext default

**Depends on:** None.

**Finding:** FND-0039 (`internal/pipeline/audits/findings/`).

**Premise verified 2026-09-23** against `origin/main @ f3e9480b` while filing (see the finding).

## Problem

`Kafka.Security.of_env` treats an absent `KAFKA_SECURITY_PROTOCOL` as Plaintext everywhere; manifests never render it; Redpanda runs without TLS/SASL in every profile; three documents claim plaintext is dev-only and that the type forces production to state its posture.

## Remediation

Stop the implicit default: `sol`-rendered manifests always set `KAFKA_SECURITY_PROTOCOL` explicitly (today: `plaintext`), and `kafka-eio-service`'s `config_of_env` returns `Error` when it is absent. Correct `PRODUCT_ARCHITECTURE.md:39`, AGENTS.md *Security on Day 1*, and `WORK_SUMMARY.md:2031` to state the actual posture (in-cluster plaintext, no SASL) and link FEAT-093 for enabling TLS. This makes the posture declared and honest; it does not by itself encrypt.

## Acceptance criteria

- Rendered Deployment/CronJob env contains `KAFKA_SECURITY_PROTOCOL` (render test).
- `config_of_env` with the variable unset returns `Error` (test).
- The three documents match the rendered posture.
- Demo/example: examples and local demo set the variable (author-facing env contract).
- TS parity: `@sol-fab/kafka` must also refuse an absent protocol — record verdict/ticket.
