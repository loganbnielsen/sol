**Depends on:** None.

Give every generated Ingress a host, so multiple services without an `ingress_host` no longer collide once ingress-nginx is installed.

## Problem

BUG-020 renders a **hostless** Ingress (no `host`, path `/`) for a `-svc` that declares no `ingress_host`, so local dev can reach it. That is only valid while there is exactly one such Ingress in the cluster: nginx routes by host+path and its admission webhook enforces uniqueness cluster-wide. Since FEAT-042 made `sol dev up` install ingress-nginx, a workspace with two services now fails `sol up`:

```
error: kubectl server-side dry-run failed: ... admission webhook
"validate.nginx.ingress.kubernetes.io" denied the request: host "_" and path "/"
is already defined in ingress ci-smoke-checkout/checkout-svc
```

(The webhook normalizes the empty host to `_`.) Observed on the golden-path smoke, whose second service comes from FEAT-041's throwaway peer, but it reproduces with any two `-svc`s in one workspace — e.g. `sol new svc` twice, or two workspaces sharing `sol-local`.

A hostless Ingress is also a catch-all in customer-cloud: it matches traffic for **any** Host, so it can silently steal requests meant for another service.

## Goal

Two services without an `ingress_host` coexist, `sol up` succeeds, and each is reachable in local dev through the ingress.

## Remediation

- In `ingress_doc` (`cli/sol/lib/sol_cli_manifest_yaml.ml`), when no `ingress_host` is declared, render `host: <k8s_name>.<namespace>.localhost` instead of omitting the host. The namespace is included because several workspaces can share one `sol-local` cluster; `<svc>.localhost` alone would collide across them. Keep TLS, the cert-manager annotation, and the ssl-redirect annotation off for this dev host (it is HTTP-only and never leaves the machine).
- Update the golden-path smoke's ingress check to send that host (`curl -H "Host: charge-svc.<ns>.localhost" http://localhost:8088/health`), deriving the namespace from the cluster the way the FEAT-041 netprobe already does.
- Update the hostless-Ingress render tests and the substrate-contract / TUTORIAL wording that still describes a "hostless" Ingress.

## Acceptance criteria

- No Ingress is emitted with an empty host.
- `sol up` succeeds for a workspace with two `-svc`s and no `ingress_host`, and each is reachable through the local ingress at `http://<svc>.<ns>.localhost:8088/...`.
- Two workspaces on the same cluster do not collide.

## Completion notes

`ingress_doc` now always renders `host:`. With no declared `ingress_host` it uses
`<k8s_name>.<namespace>.localhost` instead of omitting the host; the namespace
is part of the name because several workspaces share one `sol-local` cluster
(and two services can share a name across namespaces, e.g. the two dogfood
workspaces locally). TLS, the cert-manager annotation, and the ssl-redirect
annotation remain off for that dev host, so it is HTTP-only.

The golden-path smoke's ingress check now sends the host
(`curl -H "Host: charge-svc.<ns>.localhost" http://localhost:8088/health`),
deriving the namespace from the cluster the same way the FEAT-041 netprobe does.

Docs: `self-hosted-substrate-contract.md` and the TUTORIAL's DNS step now
describe the dev host and how to reach it, instead of a hostless Ingress.

Validation: `dune build`, `dune test cli/sol/test/` (49 tests, including the
renamed `test_undeclared_ingress_host_gets_dev_host`), `dune fmt --preview`,
and the workflow's YAML/bash syntax all pass. A two-service `sol up --dry-run`
renders two Ingresses with distinct hosts (`checkout-svc.w-checkout.localhost`,
`charge-svc.w-payments.localhost`) and no hostless `- http:` rule. Confirmed
against the real ingress-nginx admission webhook on a local k3d cluster:
`kubectl apply --dry-run=server` accepts both distinct-host Ingresses.
