`sol-jobs`: stop cross-claiming between `Make` instances, and make database failures visible without `?ot`

**Depends on:** None.

**Finding:** FND-0036 (`internal/pipeline/audits/findings/`).

**Premise verified 2026-09-23** against `origin/main @ f3e9480b` while filing (see the finding for the command/probe and observed output).

## Problem

The claim query ignores `kind` although the spec endorses multiple distinct `Make` instances on the shared table, so one instance claims, fails to decode, retries and finally marks `'failed'` another's jobs. All error reporting goes through `log_warn`, a no-op when `ot` is `None`; a missing `sol_jobs` table loops forever silently with no health signal.

## Remediation

(a) Filter the claim on kinds the `Make` handles (J declares them), or restrict the spec to one `Make` per table and release (not fail) a foreign kind. (c) Log to stderr without `ot`; verify the table at startup and return `Error`; treat N consecutive claim failures as fatal. Lease fencing (FND-0036 b) is out of scope unless trivially added by fencing finalize on `attempts`.

## Acceptance criteria

- Integration test (Postgres): two `Make` instances with different kinds never finalize each other's rows.
- `run` without `?ot` against a DB lacking `sol_jobs` returns `Error` (or exits non-zero) with a message naming the table.
- `sol-jobs.md` claim/lease section matches the behaviour.
- TS parity: sol-jobs is OCaml-only today — record verdict in completion notes.
- Demo: the local-demo jobs wiring still works; note in completion notes.

## Completion notes

- **(a) Claim by kind.** `JOB` gains `val kinds : string list`, every value `kind` can
  return. The claim adds `AND kind = ANY(string_to_array(?, ','))` with `J.kinds`
  comma-joined, so two `Make` instances sharing the fixed table claim only their own
  rows. `run` refuses empty or invalid kinds (`[a-z0-9_.-]`, so the separator cannot
  appear) with `` `Config ``. `enqueue` refuses a job whose `kind` is not in `J.kinds`,
  because no poller would ever claim it. It stays a `Pg_error.t` (`Query_error`) so
  transactional enqueue still composes with `Db.transaction`.
- **(c) Loud database failures.** Warnings fall back to stderr when there is no `?ot`.
  `run` reads the table before its first claim and returns `` Error (`Database msg) ``
  if it cannot, so a missing migration is a startup error that names `sol_jobs`.
  `?max_claim_failures` (default 30) consecutive failed claims end `run` with
  `` `Database ``; a transient blip is still retried every `poll_interval_s`.
  `run_error` gains `` `Database ``.
- **(b) Lease fencing** is BUG-050, not this ticket.
- Tests: `test_sol_jobs.ml` adds `validate_kinds`. New `test_sol_jobs_pg.ml`
  (POSTGRES_URL; skipped when unset) covers: two `Make` instances do not cross-claim;
  `enqueue` refuses an undeclared kind; a missing table is a startup error (with a high
  failure limit and a 5s timeout, so only the startup check can pass it); a table
  dropped mid-run ends `run` with `` `Database ``. All 4 were run against a disposable
  `postgres:16-alpine` container.
- Mutation checks (`audits/README.md`), all builds rc=0, each failing its own test: the
  claim without the kind filter; `enqueue` without the kind check; no startup table
  check; no failure limit (the test times out: "run kept looping on a failing claim").
- **Caveat:** CI's unit-test step does not include `framework/ocaml/sol-jobs`, so
  neither suite runs in CI today. The Postgres suite needs a database, as the Kafka one
  needs a broker.
- Demo/example: author-facing contract change (`val kinds`), so the local-demo fixture's
  `EmailJob` (`internal/fixtures/local-demo/bin/demo.ml`, `test/test_e2e.ml`) declares
  `kinds`, and `sol-jobs.md` documents it, including the claim SQL and the new errors. No
  `examples/` workspace uses `sol-jobs`.
- Language parity: sol-jobs is OCaml-only (FEAT-077). There is no TypeScript
  counterpart, so the verdict is intentionally deferred, not equivalent.
