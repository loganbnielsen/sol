**Depends on:** None.

**Premise re-verified 2026-10-01** at `origin/main @ 90ce84d9`: both DONE files still
declare `id: DEC-049`, and no GCP qualification PR is open. The latest decision id is
`DEC-059`, so use `DEC-060`. The former Terraform comment and planning summary no longer
exist; remaining GKE references also appear in decision notes, qualification status,
and historical findings.

## The defect

Two files in `DONE/` declare `id: DEC-049`, and they are different decisions:

- `DONE/DEC-049.md` — *A released Sol is self-contained, and every Sol-owned
  asset it uses is version-aligned with it* (`type: decision`, from FEAT-101).
- `DONE/DEC-049-gke-standard-is-the-supported-gcp-substrate.md` — *GKE Standard
  is the supported GCP substrate* (`type: feature`, `source: GCP qualification
  Attempt 14 (FND-0064)`, landed with INFRA-093).

`Soldev_ticket.find_ticket id` resolves an id to
`internal/pipeline/tickets/<STATE>/<id>.md`, so `DEC-049` is always the
self-contained-release decision: the GKE decision cannot be found by id at all,
and any `Depends on: DEC-049` is read against the wrong one. In `pipeline ls` the
second file is displayed under the filename stem `DEC-049-gke-standard-...`
while its own frontmatter says `DEC-049`, so the listing carries two rows for one
id. Nothing in CI read the id, which is how the collision landed green.

Remaining references that mean the *GKE* decision are INFRA-093's ticket text,
two other decision notes, qualification status, and two historical findings.

Reproduce:

```text
$ soldev pipeline check DEC-049        # answers for the self-contained-release decision
$ soldev pipeline ls --all | grep DEC-049   # two rows, one id
```

## Remediation

1. Renumber the GKE decision to `DEC-060` by renaming the file to `<id>.md` and
   setting `id:` to match;
   the file name and the declared id must be the same string, because the file
   name is what the pipeline looks up.
2. Update those GKE references without changing release-bundle references.
3. Make `soldev pipeline validate` enforce id uniqueness and id-equals-filename
   with mutation cases. The duplicate shows a readable tree can still be unusable.

## Acceptance criteria

- No two tickets in the tree declare the same id, and every id in the tree
  resolves to exactly one file.
- The GKE decision's file name, its `id:`, and its references all agree;
  no reference to DEC-049 means the GKE decision any more.
- If id/every-id checks were added to `soldev pipeline validate`, they have a
  mutation case in `internal/ci/test_pipeline_validate.sh` (planted duplicate or
  mismatched id, rejected).
- Demo/example: not applicable (internal). Language parity: no impact.
