**Audit finding:** `internal/pipeline/audits/findings/FND-0016-scoped-deploy-requires-a-closed-call-graph.md`

## The question

A scoped deploy currently requires its call graph to be inside the scope. `--scope
payments/charge_svc` fails with `service "charge_svc" calls "checkout/checkout_svc":
target service not found` — for a callee that exists, is deployed and is healthy —
because `Sol_cli_deployment_scope.Unit_named` selects exactly one unit and
`Sol_cli_deployment_plan.lookup_call` resolves call references against that
selection.

With FND-0012 (an omitted unqualified unit blocks the whole-workspace preflight),
this left the workspace with **no route that deploys all its intended services**.

## Options considered

| Option | Description | Verdict |
|---|---|---|
| 1 | Resolve call targets from the workspace inventory; leave the boundary as requested | Correct principle, but on its own it also accepts a target that does not exist anywhere |
| 2 | Widen the scope transitively to include callees | **Rejected** — changes what a *release* is, and therefore the release identity DEC-018 restores |
| 3 | Keep the closed-world rule; improve only the error message | **Rejected** — it is honest, but it unblocks nothing, and the rule itself is the mistake |
| 4 | Resolve from the workspace inventory **and fail closed** when the referenced unit does not exist | **Chosen** |

## Decision (2026-09-20) — option 4

**Deployment selection and dependency resolution are separate concepts.**

1. **`--scope` determines what is deployed, and must preserve the requested
   boundary.** A named unit deploys that unit. Nothing is added to a release
   because something else calls it or it calls something else.
2. **Call targets are resolved against the workspace inventory**, not only against
   the selected deployment units.
3. **A valid referenced service does not need to be selected for deployment in
   order to provide the manifest metadata its caller needs.** The caller needs
   `domain`, `name` and the derived URL — not the callee's liveness, and not its
   presence in this release.
4. **Resolution must still fail closed when the referenced domain or unit does not
   exist in the workspace.** A misspelling must not silently produce a deployment
   pointing at a name nothing can resolve. The failure must name what was
   referenced and what the workspace does contain.
5. **Deployment scope is never widened transitively.** If a callee is not selected,
   it is not deployed by this invocation — it is assumed to be reachable because it
   is part of the workspace. Whether it is actually running is a separate question
   that this decision does not settle, and that a health/preflight check may take
   up later.

## Why this shape

The plan's requirement is *metadata*: it computes a URL and an environment variable
from the callee's manifest. It never asks the cluster whether the callee is healthy.
Option 1 therefore satisfies the plan as written — option 4 adds the fail-closed
clause that option 1 lacks, because the current error message proves the failure
mode is real even if the message itself is wrong.

Option 2 was rejected because a release that silently grows with its dependencies
has no stable identity to roll back to, which is what DEC-018 depends on.

## Acceptance criteria

1. A scoped deploy of a unit whose call graph leaves the scope **succeeds** when
   the referenced units exist in the workspace, and the caller's environment
   carries the callee's URL.
2. A call reference to a **nonexistent or misspelled** domain/unit still **fails**,
   with a message naming the reference and the workspace's available units.
3. The deployed set is exactly the requested scope — no transitive widening, which
   the release record's workload list can demonstrate.
4. Regression coverage for both (1) and (2).

Derived ticket: `INFRA-053`.

## Consequences

- A unit can be deployed alone against an already-deployed callee. The operator is
  responsible for the callee being present, and the profile's health checks are
  where that becomes visible.
- The error message changes from "target service not found" to naming the
  reference and the available units.
- `sol rollback`'s release boundary is unchanged, because nothing widened.
