title: Reject GCP cluster names that overflow derived service-account IDs before provisioning

**Depends on:** None.

## Premise verified

`platform/cloud/gcp/cluster/main.tf` still derives the cert-manager account ID as `${var.cluster_name}-cert-manager`; no CLI preflight enforces the resulting 30-character Google limit. A 19-character cluster name failed during Terraform apply.

## Remediation

Validate the derived IDs, including the longest suffix, before billable mutation and name the offending target and allowable form. Keep Terraform's resource names and the CLI rule aligned.

## Acceptance criteria

- A too-long GCP target fails preflight before Terraform apply; the 17-character boundary passes.
- The error names the derived account ID and constraint.
- Example impact: none; this is provider target validation. Language-parity impact: none.

## Completion notes (2026-10-05)

**Premise re-verified at pickup.** `platform/cloud/gcp/cluster/main.tf` still derives `account_id` as
`${var.cluster_name}-{provisioner,loki,thanos,cert-manager}`; the longest suffix is `-cert-manager`
(13), so Google's 30-character `^[a-z](?:[-a-z0-9]{4,28}[a-z0-9])$` rule caps `var.cluster_name` at
17 characters. No CLI preflight checked it, and the 19-character `sol-qual-gcp-alpha7` target failed
inside Terraform apply.

**Fix.** `Sol_cli_gcp_cluster.validate_cluster_name` validates the id every declared suffix derives
and, on overflow, names the derived account id, the 6-30/regex constraint and the 17-character
allowable cluster-name length. `Sol_cli_provider_capabilities.validate_target` dispatches it for GCP
(the other providers are `Ok`), and `Sol_cli_environment_stage.prepare` calls it before any asset
resolution or Terraform invocation, so `sol cloud plan|apply` and `sol deploy` refuse a too-long
target before anything billable. The suffix list is ordered longest-first so the reported id is the
binding one; Terraform's resource names and `-target`s are unchanged.

**Tests.** `cli/test/inline/test_gcp_cluster.ml` covers the boundary (17 characters validates; 19 is
refused with the derived id, the 6-30 constraint and "at most 17" in the message) and pins the rule
to the Terraform root: it reads `platform/cloud/gcp/cluster/main.tf`, requires every declared suffix
to be in the CLI list, and requires the CLI's longest suffix to equal the root's longest, so the two
cannot drift. The pre-push lifecycle suite runs the GCP scenarios whose short cluster names remain
valid.

**Demo/example:** none — provider target validation. **Language parity (DEC-022):** none — no
application-facing contract.
