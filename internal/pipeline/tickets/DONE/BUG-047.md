Install the SIGTERM/SIGINT handler once per process and restore default disposition after the first signal

**Depends on:** None.

**Finding:** FND-0042 (`internal/pipeline/audits/findings/`).

**Premise verified 2026-09-23** against `origin/main @ f3e9480b` while filing (see the finding for the command/probe and observed output).

## Problem

`Sol_runtime.install_signal_handler` is called by every primitive's `run`; `Sys.set_signal` is process-global, so the last install wins and co-hosted primitives never drain. The handler outlives the pipe it writes to (fd may be reused) and swallows a second signal.

## Remediation

One lazily-installed process handler that resolves all registered stop promises; `run` registers/unregisters. After the first signal, restore default disposition so a second one terminates.

## Acceptance criteria

- Test: two registered promises are both resolved by one SIGTERM.
- Test: after the handler's switch ends, a signal does not write to the old fd.
- Demo/example: the local demo (svc+worker+jobs in one process) drains all three — note in completion notes.

## Completion notes

- `Sol_runtime.install_signal_handler` keeps its signature, so no primitive changes.
  Underneath, one handler per process is installed on the first registration and
  writes one byte to every registered self-pipe. Each call registers its own pipe
  and daemon fiber and unregisters when its switch ends: the fd is removed from the
  handler before it is closed (no write to a closed or reused fd), and when the last
  registration goes the previous SIGTERM/SIGINT dispositions are restored. A second
  signal while the first is being handled restores the default and re-raises, so a
  second Ctrl-C (or SIGTERM) terminates the process.
- Tests (`framework/ocaml/sol-runtime/test/test_signal.ml`): one SIGTERM resolves two
  co-hosted registrations; after the switch ends SIGTERM is back to
  `Signal_default`; a child process that receives two SIGTERMs dies of SIGTERM
  instead of exiting normally.
- Mutation check (`audits/README.md`): the old per-install implementation, substituted
  whole from `origin/main`, builds (rc=0) and fails all three new tests.
- Demo/example: the local demo (`internal/fixtures/local-demo`, svc + worker + jobs in
  one process) is exactly the co-hosted case this fixes; no code change is needed there.
- Language parity: TS services get SIGTERM handling from Node and `@sol-fab/*`, which
  are outside this repo, so this is not applicable to the OCaml-side runtime helper.
- Review round 1 (non-blocking, taken): the comment claimed handlers run on the main
  domain. In OCaml 5 any polling domain may run them, so the comment now states the
  single-domain assumption that registration relies on, which holds for every
  current caller.
- `internal/ci/check_signal_handler_duplication.sh` still passes: the handler lives
  only in `sol-runtime`.
