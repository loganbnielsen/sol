**Depends on:** None.

`cmd_migrate.ml`'s `default_table_name` and `Sol_cli_migration.table_name` both build `sol_<name>_schema_migrations`, kept in step only by a comment. They do not even take the same input: `sol migrate` uses `Filename.basename (Sys.getcwd ())`, while the deploy's migration gate uses the workspace name (`Sol_cli_workspace.current_name`, resolved from the root). Run `sol migrate apply` from `app/payments/`, and it writes `sol_payments_schema_migrations`, while `sol deploy` checks `sol_<workspace>_schema_migrations`: a production deploy then reports the migrations as missing.

```
$ sed -n 6,16p cli/bin/cmd_migrate.ml      # cwd basename
$ rg -n 'let table_name' -A9 cli/lib/base/sol_cli_migration.ml   # ~workspace
```

## Remediation

Delete `default_table_name`; `sol migrate` resolves the workspace like every other command and calls `Sol_cli_migration.table_name ~workspace`. `--table` still overrides.

## Acceptance criteria

- One definition of the table name.
- A test runs the default from a workspace subdirectory and gets the workspace's table.
- Demo/example: not applicable (fixes a divergence; no author-facing change). Language parity: no impact.

## Completion notes

**Premise verified (2026-09-27):** `rg -q 'let default_table_name' cli/bin/cmd_migrate.ml` matched on `main` at `19260367`, and the definition used `Filename.basename (Sys.getcwd ())`.

The same cwd-for-workspace mistake was in two more places in `sol migrate`, fixed with it:
- `--dir` defaulted to `db/migrations` under the cwd, so from a subdirectory `sol migrate` found no migrations. The deploy gate already read the workspace root.
- The in-cluster runner took its workspace (and so its namespace and image) from the cwd basename.

`Sol_cli_workspace.migrations_dir` and `migrations_table` are now the one definition of each default, resolved from the workspace root. A flag still wins, relative to the shell, as BUG-057 set for `--var-file`. The test calls both from `app/payments/` and gets the workspace's directory and the table the deploy gate reads; on the old code it would have got `sol_payments_schema_migrations`.

Checked and left: `cmd_plan.ml` defaults its displayed project name to the cwd basename when `sol.yml` names none. That is display only, not a shared identity.
