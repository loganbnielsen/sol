`sol-jobs`: fence finalize statements on the claimed attempt and report lease overruns

**Depends on:** None.

**Finding:** FND-0036 (`internal/pipeline/audits/findings/`).

**Premise verified 2026-09-23** against `origin/main @ f3e9480b` while filing (see the finding).

## Problem

Leases are set once and never renewed; `complete_q`/`retry_q`/`fail_q` are keyed on `id` only, so a handler that outlives `lease_s` runs concurrently with a re-claim and a stale holder can clear the new holder's lease.

## Remediation

Add `AND attempts = ?` (the value the claim returned) to all three finalize statements so a stale holder's write is a no-op; log (stderr and `ot`) when a finalize affects 0 rows or when handle duration exceeds `lease_s`. Renewal stays out of scope.

## Acceptance criteria

- Postgres test: re-claim after lease expiry, then the stale holder's finalize changes nothing.
- A lease overrun is logged.
- `sol-jobs.md` lease section updated.
- Demo/example: state applicability in completion notes.

## Completion notes (2026-09-24)

Premise re-checked against `origin/main @ 4cafc74a` (after BUG-044): `complete_q`,
`retry_q` and `fail_q` still matched `WHERE id = ?` only.

- The three finalize statements match `id = ? AND attempts = ?` (the value the
  claim returned) with `RETURNING id`; a zero-row result logs
  `sol-jobs: lease lost` (`job_id`, `attempt`, `action`), through `ot` or stderr.
- A handler that ran longer than `lease_s` logs `sol-jobs: lease overrun`
  (`elapsed_s`, `lease_s`) even when its own fenced finalize still wins.
- Metrics are unchanged. `sol_jobs_processed_total{status}` still counts handler
  outcomes, and no new label value was added.
- Tests (Postgres, `test_sol_jobs_pg.ml`, "lease fencing"): the handler simulates
  a second poller's re-claim (attempts+1, fresh lease), then returns. A stale
  complete, fail or retry leaves the new holder's row pending, locked and
  un-errored, and the lost lease is logged. A 0.3s handler with `lease_s:0.1` logs
  the overrun. Ran against postgres:16: 8/8 pass.
- Mutation checks (each built and failed only its intended test): the complete,
  retry and fail statements each unfenced (`attempts >= 0 * ?`), and the overrun
  log disabled.
- Docs: `sol_jobs.mli` `?lease_s`, and `sol-jobs.md`'s claim/lease section now
  states that leases are not renewed and describes the fencing.
- **Demo/example:** not applicable. There is no author-facing API change; the
  runtime behaves differently only when a handler outlives its lease. The
  local-demo EmailJob is unaffected.
- **Language parity:** `sol-jobs` is intentionally deferred for TypeScript
  (DEC-022). The spike's capability-matrix row now records claim-by-kind and
  attempt-fenced finalize as part of the contract TS must implement.
- FND-0036 (b) → `FIXED_UNQUALIFIED`.
