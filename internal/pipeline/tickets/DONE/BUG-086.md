Pass target location to GCP node-pool and Cloud NAT inventory checks

**Depends on:** None.

**Premise verified (2026-09-29):** At `3f662e7b`, traced `Sol_cli_gcp_absence.checks` and ran the installed `gcloud` commands with `--project=probe --quiet` and no credentials. `container node-pools list` refused with `One of [--location, --zone, --region] must be supplied`; `compute routers nats list` refused with `Underspecified resource ... Specify the [--router-region] flag`.

## Problem

The GCP inventory receives `target.region` but omits it from the node-pool and Cloud NAT commands. Both location-scoped commands fail before reaching the provider unless the operator has configured a matching default region. A different configured default can also query the wrong location. The failures become `Unobservable`, preventing a complete independent absence verdict and hiding recoverable resources from reconciliation.

## Recommended direction

Supply the target's region/location explicitly on every location-scoped provider command. Keep the location derived from the resolved target, not the user's mutable gcloud configuration.

## Acceptance criteria

- Node-pool and Cloud NAT checks pass explicit target location flags accepted by the installed `gcloud` commands.
- Tests inspect/execute the generated argv with no configured default region and show the target region wins over a conflicting default; failure remains `Unobservable`.
- A successful empty result and a present result retain their existing classification, and the acceptance covers both affected resource classes.
- Completion notes explain why an app-author demo and language-parity change are not applicable to this cloud safety correction.

## Completion (2026-09-29)

- **Premise re-verified** at `origin/main`: `Sol_cli_gcp_absence.checks` received `region` but passed it only to the Artifact Registry check, so `gcloud container node-pools list --cluster X` and `gcloud compute routers nats list --router X` failed before reaching the provider (`One of [--location, --zone, --region] must be supplied`; `Underspecified resource ... Specify the [--router-region] flag`), and both classes were `Unobservable` on every account.
- **Change.** The node-pool check carries `--location <target region>` and the Cloud NAT check `--router-region <target region>`. Two more regional commands in the same inventory — `compute routers list` and `compute networks subnets list` — take `--region <target region>` as well: the audit's remediation is "supply the target's region on every location-scoped command", and those two otherwise follow the operator's mutable `CLOUDSDK_COMPUTE_REGION`, which can silently point the inventory at a different region. Global commands (`networks list`, `addresses list --global`, Cloud SQL) are unchanged, and Artifact Registry already passed `--location`.
- The location always comes from the resolved target, never from gcloud's configuration.
- **Tests.** New `cli/test/test_gcp_absence.ml` drives `observations` against a stub `gcloud` on `PATH` that records every argv, with `CLOUDSDK_COMPUTE_REGION=europe-west1` set to a conflicting default. Five cases: every regional check carries `--location`/`--router-region`/`--region` with the target's region; no check follows the default region; an empty inventory leaves both classes `Absent`; a present node pool and NAT are `Present`; a refused list is `Unobservable` carrying gcloud's reason. Mutation-checked — dropping `--location` fails the first case.
- Demo/example: not applicable — a language-neutral CLI/cloud safety correction to how Sol interrogates the provider, with no app-author surface change and no example that runs GCP inventory. Language parity: no impact (the TypeScript runtime does not run provider inventory).
