**Depends on:** None.

`docs/reference/cli.md` is generated from the binary's own help, and
`internal/ci/check_cli_reference.py` fails when the page and the binary disagree — an undocumented
command, a command the binary does not register, or a flag a command does not have.

**The guard did not run on the path where the drift can enter.** The classifier treated a change to
`docs/reference/cli.md` as `docs-only`, and the docs-only fast path deliberately skips every guard.
Run rather than reasoned — the script takes a file list, not a path, and an unknown argument makes it
emit `source`:

```text
$ printf 'docs/reference/cli.md\n' > /tmp/paths
$ internal/ci/classify-changes.sh --files-from /tmp/paths
docs-only

$ printf 'cli/bin/main.ml\n' > /tmp/paths          # positive control
$ internal/ci/classify-changes.sh --files-from /tmp/paths
source
```

The rule was the classifier's own fall-through, where `docs/*` and `*.md` both mean prose, and the
guard that would catch a hand-edited command row ran only on the other path:

```text
$ grep -n -A 2 check_cli_reference .github/workflows/ci.yml
701-        if: needs.classify.outputs.kind != 'docs-only' || steps.docs_tooling.outputs.cache-hit != 'true'
702:        run: python3 internal/ci/check_cli_reference.py
```

So a PR that edited a command row — the one drift the guard exists to catch — took the fast path,
where the guard, its mutation test and the product build were all skipped. The fast path restores
only a cached *soldev* binary, so the guard could not simply be added there: there is no
`cli/bin/main.exe` for it to read.

## Status

**Done** — the change landed in PR #784 and is on `main`. This ticket was filed in
`READY_FOR_ENGINEERING` only because a new ticket may not appear directly in `DONE`; it moves here
with no work performed in between. It exists because the fix merged under the id `BUG-108`, which
another fix concurrently claimed and then replaced, leaving the classifier change undocumented in
the ticket tree. The evidence and completion notes below are the record.

## Remediation

Classify the generated page as an artefact of the code rather than as prose: `classify-changes.sh`
keeps a list of generated artefacts — one entry today, `docs/reference/cli.md` — and routes a path on
that list to `source` before the prose allowlist is consulted.

**Cost, deliberately accepted:** regenerating the page after a CLI change now runs the full suite.
That is the right price for a generated artefact, and the alternative was a guard that could not run
on the path where the drift enters.

## Preventing the next collision (2026-10-01)

Recovering this record fixed the instance. The mechanism is worth naming, because nothing in the
tree stopped it: **ticket ids are allocated by whoever needs one**, so two actors reading the same
`main` both chose `BUG-108`, and the second record landed on the path the first already occupied.

What actually happened, from the two diffs: the losing branch merged second, and its change to
`internal/pipeline/tickets/DONE/BUG-108.md` was an ordinary modification — a modify of a finished
record, which the transitions guard skips (`/^M/ { next }`) because editing a DONE ticket is
legitimate. `git mv` is not the quiet path here: it refuses to overwrite an existing file.

`internal/ci/check_ticket_overwrites.py` closes the three ways a record can be replaced, and each
fails with the reason under test:

- a **move onto an occupied path** (`git mv -f`, or a manual write) — refused, naming the record
  already there;
- a **new ticket reusing a taken id** — refused, naming where that id already lives, which is the
  check that tells the second actor to take the next free id at filing time;
- a **finished record whose `title:` changes** — refused with the before/after titles, because a
  different defect under the same id is exactly this failure. An in-flight ticket may be reworded
  freely, and a genuine correction to a finished record is allowed by saying `(title correction)`
  in a commit subject.

It runs in CI with `internal/ci/test_ticket_overwrites.py` — ten cases: each refusal with its
reason, the honest cases that must pass, and one real in-place replacement in a scratch
repository.
