**Depends on:** None.

**Premise** (checked 2026-10-01, `origin/main` after #849): `Soldev_ticket.parse_depends`
reads only the line that starts with `**Depends on:**`
(`internal/tooling/soldev/lib/soldev_ticket.ml`). A field wrapped onto later lines loses
any ids there with no warning, so `/work` can schedule a ticket before a dependency its
author declared. DEC-029 lost `DEC-027` this way until #849 put its field on one line.
An audit of every ticket finds no other dropped id today, but eight tickets wrap the
field with prose (INFRA-015, RELEASE-005, SEC-005, FEAT-078, FEAT-085, INFRA-016,
INFRA-023, INFRA-017), so nothing stops the next one.

## Remediation

AGENTS.md already defines the field as one line ("every ticket id on that line becomes a
dependency"). Enforce that definition instead of widening the parser. Reading the whole
paragraph would turn ids mentioned in prose into dependencies, which AGENTS.md warns can
deadlock.

- `Soldev_ticket.unreadable` (run by `soldev pipeline validate`, which CI runs on every
  PR) rejects a `**Depends on:**` line followed by a non-blank line, and names the fix:
  keep the field on one line and put commentary in its own paragraph.
- Reflow the eight tickets above so each field is one line.
- AGENTS.md § *Ticket dependencies* states the one-line rule and that validate enforces
  it.

## Acceptance criteria

- A unit test: a wrapped field is reported as unreadable, and a one-line field followed
  by a blank line is not.
- `soldev pipeline validate` passes on the reflowed tree, and each reflowed ticket's
  parsed dependencies are unchanged.
- Demo/example: not applicable (internal tooling).

## Completion notes (2026-10-01)

- `Soldev_ticket.unreadable` now rejects a wrapped field. Like `parse_depends`, it
  checks only the first `**Depends on:**` line. A following `**Related:**`-style bold
  field or a heading starts a new block, so it is not a wrap. The first validate run
  without that rule flagged six correct tickets.
- The eight wrapped tickets were reflowed. Each one's parsed dependencies are unchanged
  (SEC-005 and INFRA-023 still start with `None.`). INFRA-015 and INFRA-017 also got a
  `title:`: without one, their listing title had been a line from the wrapped field.
- Tests: `test_wrapped_depends_is_unreadable`, `test_one_line_depends_is_readable`. The
  existing "every ticket in the pipeline tree is readable" test covers the whole tree.
- Demo/example: not applicable (internal tooling). No language-parity impact.
