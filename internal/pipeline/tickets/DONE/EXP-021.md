`sun deploy` does not print service URL on completion; `sun status` does not show deployed image version

**Description:** Two related gaps. (1) `sun deploy` completes with "Done. N service(s) deployed. Run 'sun status' to check pod health." but does not print the service URL. The Stage 5 invariant requires the command to print the deployed service URL on completion. (2) `sun status` runs `kubectl get pods -n <ns>` (NAME/READY/STATUS/RESTARTS/AGE) but does not show the deployed image tag. The Stage 7 invariant requires "health, version, and endpoint for every deployed service."

**Impact:** After `sun deploy`, the engineer must run a separate command to discover the endpoint. After `sun status`, they cannot confirm which version is live without kubectl knowledge — making it harder to verify a rollout completed correctly.

**Remediation:** (1) In `cmd_deploy.ml`, after deploying, query `kubectl get svc -n <ns>` for each HTTP service and print its port-forward hint (same logic as `cmd_status.ml`). (2) In `cmd_status.ml`, use `kubectl get pods -n <ns>` with a custom-columns format or jsonpath to include the image tag in the status output alongside the existing NAME/READY/STATUS/RESTARTS/AGE columns.
