The scaffolded schema-compatibility gate is never run: it is an executable, not a test

**Depends on:** None.

**Finding:** FND-0040 (`internal/pipeline/audits/findings/`). Found in BUG-049's review.

**Premise re-verified 2026-10-02** on `origin/main @ 9f68429f`:
`platform/shared/templates/workspace/test/dune` still declares
`(executable (name test_schemas))`, while the generated workflow runs
`dune runtest`. The generated test already fails under `CI` without a registry,
but CI never discovers it.

## Problem

A generated workspace's CI passes without ever checking schema compatibility. The
tutorial presents the gate as blocking breaking changes before staging.

## Decision

Operator confirmed 2026-10-02: CI requires a configured registry containing
published schema history and fails when it is absent or the check cannot run.
Local development may visibly skip when `SCHEMA_REGISTRY_URL` is absent.

## Remediation

Make the generated schema executable a Dune test. Pass the configured registry
URL to generated CI, and document that it must point to published schema
history in the generated README and `TUTORIAL.md`.

## Acceptance criteria

- A generated workspace's CI either runs the gate against the configured registry or
  says visibly that it did not.
- Demo/example: scaffold templates are the demo; state in completion notes.

## Completion notes

The scaffolded `test_schemas` is now a Dune test, so the generated workflow's
`dune runtest` executes it. That workflow supplies `SCHEMA_REGISTRY_URL` from a
required GitHub Actions secret. The existing test fails under CI when the URL is
unset or the registry check fails; local runs visibly skip when it is absent.
The generated README and tutorial explain that CI must target the registry with
published history. The runnable workspace scaffold is the updated example.
No language-parity impact: this is the OCaml scaffold's existing schema gate;
the TypeScript golden path is tracked separately and its runtime schema semantics
are unchanged.

Focused scaffold regression `ci_workflow/8` passed. The broader `cli/test`
suite first exposed that its nested scaffold test inherited `CI=true` without a
registry; the local scaffold test now sets `CI=false` explicitly. Required CI
checks the full suite.
