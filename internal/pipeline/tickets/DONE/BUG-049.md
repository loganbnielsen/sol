Enforce FULL schema compatibility for real: set it before registering, fail on error, and make the CI gate fail instead of skip

**Depends on:** None.

**Finding:** FND-0040 (`internal/pipeline/audits/findings/`).

**Premise verified 2026-09-23** against `origin/main @ f3e9480b` while filing (see the finding).

## Problem

`register` sets FULL after registering and only warns on failure; `Schema.check` treats any HTTP 404 as "no prior version"; the scaffolded `test_schemas.ml` exits 0 when `SCHEMA_REGISTRY_URL` is unset and checks a hand-written list. The spec lists enforcement as out of scope while code and tutorial rely on it.

## Remediation

Adopt the contract the code and tutorial already assume (FULL enforced): PUT `/config/<subject>` FULL before the first registration and return `Error` if it fails; in `check`, treat 404 as absent only for error code 40401 (parse body), else error; scaffold gate exits non-zero when `CI` is set and the registry URL is absent, and enumerates messages from the events packages rather than a literal list; move compatibility enforcement out of the spec's Out-of-Scope list.

## Acceptance criteria

- Unit tests for the 404-body cases (40401 → Ok, other 404 → Error) and for compat-PUT failure failing `register`.
- Scaffolded gate fails under `CI=1` without a registry.
- Demo/example: scaffold template change — regenerate/verify the example workspace.
- TS parity: record whether `@sol-fab/kafka` registration order matches (FEAT-034 history).

## Completion notes

Registry behaviour, verified against the local Redpanda schema registry (2026-09-24):
`POST /compatibility/subjects/<new>-value/versions/latest` returns
`404 {"error_code":40401,...}`; a wrong base path returns
`404 {"error_code":404,...}`; `PUT /config/<subject>` with FULL succeeds before any
version exists, and `GET` then shows `FULL`.

- **FULL is set before registering, and failing to set it is fatal.**
  `Kafka_service.register` PUTs `{"compatibility":"FULL"}` before `POST
  /subjects/.../versions` and returns `Schema_registry` if the PUT fails. (It used to
  register first and only warn.)
- **`Schema.check`:** a 404 means "no version yet" only when the body's `error_code` is
  40401 or 40402 (`Schema.is_subject_not_found`, exposed for tests). Any other 404 is an
  `Error` that names the registry URL. 40402 is included deliberately: "version not
  found" for `latest` also means nothing is registered to be compatible with.
- **Scaffolded gate** (`test/test_schemas.ml` template): under CI (`CI` set) a missing
  `SCHEMA_REGISTRY_URL` exits 1 instead of skipping; on a developer machine it still
  skips. The template tells the author to list every `MESSAGE` module. **Deviation:** the
  ticket suggested deriving the list from the events packages automatically. That needs
  a generated module list maintained by `sol`, which is a bigger scaffold change, so it
  is not done here; the list stays explicit and says so.
- **Spec:** `kafka-eio-service.md` drops "compatibility enforcement" from Out of Scope
  and states the contract (FULL, set first, fatal; 404 semantics; the gate's CI rule).
- Tests: unit `is_subject_not_found` (40401/40402 yes; plain 404, HTML, empty no).
  Broker-backed: `check` through a wrong base path is an error; `register` against a stub
  registry whose PUT fails returns `Schema_registry` and sends no registration.
- Mutation checks (`audits/README.md`), builds rc=0: "any 404 is compatible" (a guard
  mutant; a first attempt removing the guard was rejected by the compiler as a redundant
  case, so it was invalid and is not counted) fails the wrong-path test; the pre-change
  `kafka_service.ml` (register first, warn-only PUT) fails the stub-registry test.
- **Caveat:** the broker-backed tests are in the `kafka-eio-service` integration suite,
  which CI does not run (see BUG-043); they were run against the local Redpanda.
- Demo/example: the scaffold template changed (author-facing CI behaviour); no example
  workspace carries a `test_schemas.ml`, and CI's golden-path smoke builds the scaffold.
- Language parity: `@sol-fab/kafka` (TS) registers schemas in its own repository;
  whether it sets FULL before registering is unassessed here (FEAT-034's history
  records registration-order bugs there). Recorded, not claimed equivalent.
