The database-backed suites are served from cache, and one of them describes a stale job table

**Depends on:** None.

**Premise verified (2026-10-02):** At `origin/main` `d025bfed`. `.github/workflows/ci.yml`'s *Framework integration tests* step ran `dune test framework/ocaml/sol-jobs/ framework/ocaml/sol-outbox/` without `--force`, after the unit step had already run those same two targets with `POSTGRES_URL` unset — where their database cases skip themselves with `[skip] POSTGRES_URL not set`. And `framework/ocaml/sol-outbox/test/test_sol_outbox.ml`'s `jobs_ddl` still created `sol_jobs` without the `workspace` column BUG-091's `enqueue` writes. Running `dune test framework/ocaml/sol-outbox/ --force` against a fresh database failed with `column "workspace" of relation "sol_jobs" does not exist`, which is how the stale table was found.

## Problem

Two things compound. The outbox suite's job table no longer matches the contract its composition test exercises — `Jobs.enqueue` inside the outbox's transaction — so that test cannot pass against a real database. And the CI step that is supposed to run both suites with `POSTGRES_URL` set does not actually re-run them: dune serves the targets from the unit step's cache, where the database cases skipped, so a suite that cannot pass stays invisible. BUG-091's own notes record fixing the local-demo fixture for this column and missing this one.

The same step runs both suites in one invocation although they share one database and each drops and recreates the one `sol_jobs` table, so either can drop it under the other. Observed directly while verifying: `relation "sol_jobs" does not exist` in the middle of a suite, from the other suite's `DROP TABLE IF EXISTS`.

## Remediation

Give the outbox suite's job table the contract `sol-jobs` actually writes, make the integration step run both suites for real (forced, and one invocation each so they cannot interleave), and cover the one boundary the isolation regression does not: that a poller's retention sweep cannot delete another workspace's terminal rows.

## Acceptance criteria

- `dune test framework/ocaml/sol-outbox/ --force` passes with `POSTGRES_URL` set.
- The CI integration step's two `dune test` invocations are forced and sequential, so the Postgres cases run there rather than being cached.
- A poller in one workspace leaves another workspace's expired terminal row alone, and removing the sweep's workspace predicate fails that case.
- `validate_workspace`'s refusals are covered by a unit test.

## Completion notes

- **The outbox suite's job table was stale.** `jobs_ddl` now creates `workspace TEXT NOT NULL` and the dedupe index as `(workspace, kind, dedupe_key)`, matching `sol-jobs`' contract and `test_sol_jobs_pg.ml`'s DDL. `dune test framework/ocaml/sol-outbox/ --force` with a real database is green (7 cases), and its composition assertion — a job enqueued inside the outbox transaction — is now the check that the two packages agree on the table.
- **The CI step runs what it claims.** The single cached invocation became two forced ones, `dune test framework/ocaml/sol-jobs/ --force` then `dune test framework/ocaml/sol-outbox/ --force`, with a comment saying why each half matters: without `--force` the targets are served from the unit step's cache, where the database cases skipped, and in one invocation either suite can drop the one `sol_jobs` table under the other. This is the change that would have caught the stale table above.
- **The sweep boundary is covered.** `test_sol_jobs_pg.ml` gains *a poller sweeps only its own terminal rows*: `alpha` completes a job and its terminal row is aged past any retention, then a `beta` poller runs with `terminal_retention_s:0.0` and must leave that row alone. **Mutation check:** replacing the sweep's `workspace = ?` predicate with a typed always-true one (`?::text IS NOT NULL`) fails exactly that case and nothing else; restored, rebuilt, green.
- **Two false starts are worth recording.** The first mutation used an untyped `? IS NOT NULL`, which made Postgres unable to infer the parameter's type: the sweep then failed *silently* — `sol-jobs` logs a failed sweep and carries on — so the test passed and the mutation looked harmless. A mutation that breaks the query rather than the predicate is not a mutation of the predicate. And the new case was first written with an unbounded poller, which simply polls forever when it has nothing to claim; it is now bounded the way the suite's own isolation case is.
- **The identity's shape is unit-covered.** `test_sol_jobs.ml` gains `validate_workspace`: a plain name, dots/dashes/case accepted; empty, whitespace-only, inner space, slash and over-63-characters refused.
- **Demo/example:** not applicable — this ticket changes test fixtures, one regression test and CI sequencing, none of which an app author runs or reads. **Language parity (DEC-022):** no application-facing change; the `workspace`-on-the-job-module contract BUG-091 introduced is unchanged.
