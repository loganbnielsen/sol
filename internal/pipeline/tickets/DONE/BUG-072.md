Preserve scheduled execution policies in release identity and rollback

**Depends on:** None.

**Premise verified (2026-09-28):** Traced `cli/lib/deploy/sol_cli_deployment_plan.ml:191; cli/lib/base/sol_cli_release_id.ml:1-22,101; cli/lib/deploy/sol_cli_release.ml; cli/lib/deploy/sol_cli_rollback.ml:156-157` with callers and existing tests at origin/main `2dfa5694`. Evidence and reproduction limits are recorded in the source audit.

## Problem

Release workload projection, hashing and stored JSON omit scheduled_concurrency and backoff_limit. Rollback reconstructs every function as Allow with backoff_limit 3. A Forbid/0 function can return as an overlapping retrying job; changing only these settings also leaves the release ID unchanged.

## Remediation

Carry both scheduled execution fields through the existing release projection, canonical identity encoding, JSON validation/storage and reconstruction. Update the encoding version coherently; no compatibility shim is required in this pre-alpha repository.

## Acceptance criteria

- A Forbid/backoff_limit=0 function round-trips spec -> release -> JSON -> rollback with exact policies; changing either policy independently changes its release ID. Rendered rollback CronJob preserves both settings. Update a runnable function example using nondefault policies.
- Record the application demo and per-language verdict in completion notes wherever the change affects an application contract.

## Completion (2026-09-29)

- **Premise re-verified** at origin/main `788e688d`: `release_workload_of_spec` projected neither `scheduled_concurrency` nor `backoff_limit`, so the release id's canonical encoding, the stored ConfigMap JSON and `decode_workload`'s rebuild all lost them; rollback hardcoded `Allow`/`3`, and editing only those two `sol.toml` settings left the release id unchanged.
- **Fix.** Both fields now travel the whole path: `Sol_cli_release_id.workload` carries `scheduled_concurrency : string` (canonical `"allow"|"forbid"|"replace"`) and `backoff_limit : int`; `release_workload_of_spec` fills them via new `Sol_cli_toml.scheduled_concurrency_to_string`/`_of_string` (which `parse_scheduled_concurrency` now reuses); the canonical encoding writes both and `encoding_version` moves `sol-release-v3` → `sol-release-v4`; `workload_to_json`/`workload_of_json` store and read them; `decode_workload` validates the concurrency string and rejects a negative `backoff_limit`, then rebuilds the spec with the recorded values instead of the defaults. No shim: the two known-vector digests (`r-41a1291ca74157ee`, `cc3f3694daa7847f57190a7bee17c417`) are updated to the v4 values (`r-9255cab6aa649011`, `1f4ea6773dd62c155c4a3ebbdad2f5c2`) and the change is recorded here.
- **Tests.** `cli/test/test_rollback.ml`: the `Fn` fixture is now `scheduled_concurrency = Forbid` with `backoff_limit = 0`, and `test_fn_reconstructs_and_verifies_as_cronjob` asserts the reconstructed spec keeps both, then renders it through `Sol_cli_deployment_render.render_spec` and requires `concurrencyPolicy: Forbid` and `backoffLimit: 0` in the CronJob YAML; `assert_spec_equal` now compares both fields for every reconstruction case. `cli/test/test_release_id.ml`: changing the concurrency alone, and changing the backoff limit alone, each change the release id. `cli/test/test_release.ml`: the ConfigMap-JSON round trip asserts `forbid`/`0` survive. **Mutation-checked**: restoring the hardcoded `Allow`/`3` in `decode_workload` fails the Fn case while the fix passes. Green: `test_release` (26), `test_release_id` (18), `test_rollback` (51), `test_manifest_render` (156), `test_deployment_phases` (51); full `dune build`, `dune fmt --preview` and `check_no_comments.sh` clean; `pipeline validate` reads all tickets.
- **Runnable example.** There is no `-fn` unit in `examples/pluto` (the repo has no runnable scheduled function), so the runnable coverage is the scaffolded-function template plus the render assertion above, which drives the real CronJob render path. `framework/ocaml/sol-fn/sol-fn.md` now states that non-default policies are part of release identity and are restored by rollback rather than reverting to `allow`/`3`.
- **Language parity: no OCaml/TypeScript contract divergence** — `scheduled_concurrency` and `backoff_limit` are `sol.toml`/manifest contracts rendered by the language-neutral CLI for any language, and the TypeScript demo has no scheduled function unit.
