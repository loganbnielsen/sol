Enforce not-before claims for verified JWT authentication

**Depends on:** None.

**Premise verified (2026-09-28):** Traced `framework/ocaml/sol-svc/lib/auth_internal.ml:213,295-315` and representative callers/tests at origin/main `6eb36b2c`. The audit records reproduced behavior, positive controls and practical limits.

## Problem

An authentically signed HS256 token with valid issuer/audience/expiration and nbf one hour in the future authenticates immediately. The selected Jose verifier checks expiration but does not enforce nbf. This permits access before the issuer's declared validity window. Fractional expiration additionally raises Type_error and becomes HTTP 500; it does not bypass expiration.

## Remediation

Validate supported temporal claims at the verified authentication boundary, enforcing present nbf and expiration semantics with finite NumericDate handling. Preserve signature verification, issuer/audience checks, and existing optional-claim policy. Convert malformed claims into typed authorization failures rather than exception-driven 500 responses. Record any intentional clock-skew policy explicitly.

## Acceptance criteria

- Signed future-nbf tokens are rejected; valid/current tokens authenticate; expired and malformed temporal claims fail safely. Include integer/fractional NumericDate boundary cases and tests through the HTTP auth adapter. Update the runnable auth example and explicitly record the TypeScript capability verdict.
- Completion notes identify runnable example/demo coverage and the per-language capability verdict, or explain why either is not applicable.

## Completion (2026-09-29)

- **Premise re-verified** at origin/main `788e688d`: `verify_with_key_source` called `Jose.Jwt.validate ~now`, which checks signature + `exp` only, and its `check_expiration` reads `exp` with `to_int_option`, so a signed token whose `nbf` is an hour ahead authenticated immediately, and a fractional temporal claim could surface as a raised `Type_error` (500).
- **Fix.** The verified path now separates signature verification from claim validation: `Jose.Jwt.validate_signature` authenticates the token (with an exception guard that maps any non-cancellation failure to a typed `Unauthorized`), then `check_temporal_claims` reads `nbf` and `exp` directly from the verified payload as finite NumericDates (`Int` or `Float`; `Null`/absent means no constraint) and rejects `now < nbf` and `now >= exp` as `Unauthorized`. A present but non-numeric temporal claim is a typed 401, not a raised 500. Signature, `alg` allowlist, issuer, audience and scope checks are unchanged.
- **Explicit policy: no clock-skew allowance** — issuer and verifier are expected to agree on time and a token outside its declared window is rejected exactly. Recorded in `framework/ocaml/sol-svc/sol-svc.md` step 4 of the verified flow, which now describes `validate_signature` + direct `nbf`/`exp` handling.
- **Tests.** `test_auth.ml` (`jwt_verified` group): future integer `nbf` → 401, current `nbf` → ok, fractional `nbf`/`exp` in range → ok, fractional expired `exp` and fractional future `nbf` → 401, and `exp`/`nbf` as string/array/object/boolean → 401 (the malformed cases previously raised). `test_service.ml` drives the same boundary through the HTTP adapter via `Service.For_testing.dispatch`: a valid verified HS256 token → 200, a future-`nbf` token → 401 (not 500), a malformed `exp` → 401 (not 500). **Mutation-checked**: removing the `check_temporal_claims` call makes the future-nbf case fail. 37 auth and 30 service tests pass.
- Validation: `dune fmt --preview` clean; no-comments policy holds.
- **Runnable example/demo**: there is no runnable auth/JWT example or scaffold sample in the tree to update (no `examples/` or template route uses `Verified_signature_required`); the app-author-facing contract lives in `framework/ocaml/sol-svc/sol-svc.md`, which is updated. **Language parity: not applicable** — the TypeScript `-svc` framework implements no Sol JWT middleware, so there is no second implementation to diverge; any future TS auth surface is bound by this same temporal contract.
