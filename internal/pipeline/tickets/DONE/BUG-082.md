Fail closed when the migration directory cannot be inspected

**Depends on:** None.

**Premise verified (2026-09-28):** Traced `cli/lib/base/sol_cli_migration.ml:54-82; cli/lib/deploy/sol_cli_migration_gate.ml:verify; cli/lib/workspace/sol_cli_workspace_scan.ml:fold_dir,discover_migrations` and representative callers/tests at origin/main `6eb36b2c`. The audit records reproduced behavior, positive controls and practical limits.

## Problem

Sol_cli_migration.required catches every Sys_error from readdir and returns Ok []. An existing unreadable directory or regular file at the migrations path therefore becomes No_migrations in the production deployment gate. Workspace discovery also warns and substitutes an empty list. The schema prerequisite can be skipped because inspection failed.

## Remediation

Distinguish a genuinely absent optional migrations directory from permission, wrong-kind and other inspection failures. Propagate those failures through migration prerequisite verification and safety-sensitive discovery; retain the documented empty result for absence and truly empty directories.

## Acceptance criteria

- Existing readable migration directories yield their required set; absent/empty optional directories preserve existing behavior. Permission-denied, file-instead-of-directory and other inspection failures yield Unavailable/Error and refuse deployment before workload mutation. Add a gate regression with an unreadable-directory case, not only a decoder unit check. Record the internal safety correction and demo/parity applicability.
- Completion notes identify runnable example/demo coverage and the per-language capability verdict, or explain why either is not applicable.

## Completion (2026-09-29)

- **Premise re-verified** at origin/main `788e688d`: `Sol_cli_migration.required` was `match Sys.readdir dir with exception Sys_error _ -> Ok []`, so an unreadable directory (EACCES) or a regular file at `db/migrations` became `[]`, the gate reported `No_migrations`, and the production deploy skipped its schema prerequisite. `Sol_cli_workspace_scan.fold_dir` likewise warned and substituted `[]` for `Unreadable`, so `Sol_cli_workspace_model.load`'s `migrations` (which feeds `sol rollback`'s "applied since this release" computation) silently read as empty.
- **Fix.** `Sol_cli_migration.inspect_directory` classifies the path with `Unix.stat` into `Absent` (only `ENOENT`), `Entries` (a directory whose `Sys.readdir` succeeds) and `Uninspectable` (any other stat error, an EACCES/`Sys_error` on readdir, or a non-directory kind, each with the path and reason). `required` keeps `Ok []` for `Absent` and a truly empty directory and returns `Error` for `Uninspectable`, which `Sol_cli_migration_gate.verify` already turns into `Unavailable` → `Failed` in `sol_cli_deploy_run.migration_prerequisite`, invoked before any workload mutation (`cmd_deploy.ml:233`, ahead of `Sol_cli_deploy_run.apply`). `Sol_cli_workspace_scan` gained `fold_dir_result` (absent → `Ok init`, unreadable → `Error`) and `discover_migrations` now returns a `result` that `Sol_cli_workspace_model.load` propagates; the advisory scans (schema subjects, topics) keep the warning behaviour.
- **Tests.** `cli/test/test_migration.ml`: a regular file at the migrations path and a `chmod 000` directory both yield `Error` naming the path (the permission case asserts only for a non-root euid). `cli/test/test_migration_gate.ml`: a new `verification gate` group calls `Sol_cli_migration_gate.verify` (no cluster contact — `required` is evaluated first) and asserts `Unavailable` naming the path for both the file and the unreadable-directory case, with a positive control that an absent and an empty directory are still `No_migrations`. **Mutation-checked**: restoring `Uninspectable -> Ok []` fails three cases in each suite while the fix passes (20 and 8 tests). Also green: `test_deployment_plan` (86), `test_workspace_model`, `test_deployment_phases`, `test_migration_job`, `test_release`; full `dune build`, `dune fmt --preview`, `check_no_comments.sh` and `pipeline validate` clean. These runs are uid 1000, so the permission cases are genuinely exercised rather than skipped.
- **Docs.** `docs/deployment/migration-ordering.md` now lists an uninspectable `db/migrations` among the `Unavailable` causes and states that an absent/empty directory is *not* that case.
- **Demo/parity: not applicable** — maintainer-side deploy safety for the migration prerequisite; no app-author surface, `sol.toml` field, framework primitive or generated manifest changes, and the check is language-neutral (it inspects the workspace's migration directory regardless of workload language).
