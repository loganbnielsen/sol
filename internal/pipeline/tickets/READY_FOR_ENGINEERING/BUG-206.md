**Depends on:** None.

## Premise verified

`platform/cloud/modules/platform/main.tf` still gives Redpanda a 600-second Helm timeout. Both released alpha.7 runs ended at `module.platform.helm_release.redpanda` with `context deadline exceeded` after about 700 seconds. No current ticket owns this paired failure.

## Evidence and limit

GCP attempt 5 provisioned GKE and Cloud SQL and applied platform prerequisites. Its API probe then recorded ten failed connections from the harness host. The post-failure capture found no Redpanda pods, PVCs or Helm release Secret, although four nodes were Ready when captured. Earlier Kubernetes events contain node startup scheduling and mount failures, but their timestamps do not establish that they blocked Redpanda. AWS attempt 2 reports the same Terraform resource and error. These observations identify the failed boundary; they do not prove whether endpoint reachability, Helm/Kubernetes API calls, chart admission, scheduling, storage or the timeout caused it. A longer timeout alone is not an established fix.

## Remediation

First reconstruct the install timeline from Terraform/Helm logs and provider-side cluster/API evidence. On the next authorized disposable run, capture API reachability concurrently from the provisioner and a separate authorized vantage point, the Helm release status/history, Redpanda objects/events, and the exact first failed operation. Determine whether Helm submitted the release at all. Only then change the shared platform install or its precondition and verify convergence on both providers without weakening readiness.

## Acceptance criteria

- A dated mechanism record states the earliest failing operation and explains both runs or explicitly records any distinct causes.
- A focused check reproduces the identified failure boundary and validates the change; a live rerun requires its own authorized run ticket.
- The fix is checked against both provider renderings. Separately authorized live run tickets establish `Ready` with healthy Redpanda before either provider's blocked app rows are credited.
- Example impact: none; this repairs the internal platform lifecycle. Language-parity impact: none; both app languages consume the same platform.
