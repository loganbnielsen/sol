Docs-only CI still bootstraps OCaml and runs unrelated guard suites

**Depends on:** None.

## Finding and premise verification

Verified 2026-09-28 on PR #646, run 36386082306: Markdown-only changes
classify as docs-only and skip product tests and smoke jobs, but the test job
continues through OCaml setup, package pinning, dependency installation, guard
binary builds, and unrelated guard mutation suites. It remained in progress
well beyond the expected roughly 15-second validation path.

Evidence commands: `gh run view 36386082306 --json status,conclusion,jobs` and
`rg -n 'docs-only|unconditional|setup-ocaml|opam' .github/workflows/ci.yml`.
Positive control: the product test/smoke conditions correctly exclude docs-only;
the unconditional tooling step deliberately does not. This is slow execution,
not an incorrect docs-only classification.

BUG-064 made tooling unconditional to stop docs-only checks failing because
their binaries were missing. Preserve that correctness fix while removing the
expensive bootstrap from the documentation fast path.

## Remediation

- Give allowlisted Markdown-only changes a lightweight required CI path without
  product toolchain installation, product builds/tests, or unrelated mutation suites.
- Preserve relevant ticket/frontmatter/dependency/transition validation. Reuse the
  authoritative parser, through a cached/prebuilt artifact or another minimal existing
  execution path; do not introduce a second interpretation of ticket metadata.
- Preserve full validation for code/CI changes, mixed diffs, and classification
  uncertainty. Do not skip all checks solely because a filename ends in .md:
  executable premise probes and generated/scaffold assets still need appropriate checks.
- Update BUG-064's unconditional-tooling invariant and its mutation tests to reflect
  the new valid execution paths rather than weakening them silently.

## Acceptance criteria

- A real ticket-only PR skips the expensive toolchain and unrelated suites, with
  measured validation time aiming for about 15 seconds; runner queue/setup is reported
  separately rather than promised as controllable latency.
- Valid ticket filings pass; malformed frontmatter and invalid ticket transitions fail.
- Positive/negative classifier controls demonstrate a docs-only fast path and full
  checks for mixed code/docs and workflow changes; uncertainty remains fail-closed.
- No missing-tool failures recur, and no duplicate ticket parser is added.
- Demo/example and language parity: not applicable; this changes maintainer CI only.

## Implementation progress

Part A adds an exact-source cached soldev validator, saved only by trusted main
pushes. Cached docs-only runs retain classification, ticket validation/transitions/
moves, spec signatures, and account-artifact checks. Cold cache and uncertain
classification take the full source path; no alternative YAML parser is added.
Three execution-path tests, six tooling mutations, 34 classifier controls, and
ticket parser/transition/move mutation suites pass locally. Completion awaits a
real cached docs-only PR after the trusted cache has been populated on main.
