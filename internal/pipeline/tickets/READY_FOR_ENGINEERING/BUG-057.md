title: A relative terraform_var_file resolves against the invocation directory, not the workspace root
source: found while implementing REFAC-105 (2026-09-25)

**Depends on:** None.

## The defect

A target's `terraform_var_file` is passed to Terraform after `normalize_var_file` in `cli/sol/bin/cmd_cloud_tf.ml`:

```ocaml
let normalize_var_file path =
  if Filename.is_relative path then Filename.concat (Sys.getcwd ()) path else path
```

So a relative path means something different depending on where `sol` was run from. That contradicts DEC-024 clause 4, as `Sol_cli_config` states it: "Config and target paths resolve relative to the resolved workspace root, not the invocation cwd, so `sol plan`/`sol deploy` work from any descendant directory."

## Evidence

Pluto's `dev` and `customer_cloud` targets (before REFAC-105) set `terraform_var_file: ../../../../../internal/qualification/aws/smoke-test.tfvars`. That path was clearly written relative to the target file's own directory:

```
$ cd examples/pluto && realpath -m ../../../../../internal/qualification/aws/smoke-test.tfvars
/home/logan/internal/qualification/aws/smoke-test.tfvars          # does not exist
$ cd sol/dev/aws && realpath -m ../../../../../internal/qualification/aws/smoke-test.tfvars
/home/logan/Code/sol-cloud/sol-REFAC-105-pluto/internal/qualification/aws/smoke-test.tfvars   # exists
```

`sol cloud apply dev/aws/us-east-1` run from the workspace, which is how `live-smoke.sh` invoked it, would have handed Terraform a var file that doesn't exist. REFAC-105 removed that reference, but not the resolution rule.

## Remediation

- Resolve a relative `terraform_var_file` against the **workspace root** (`Sol_cli_config.workspace_root ()`), not `Sys.getcwd ()`. That is the rule DEC-024 clause 4 already applies to config and target paths.
- Leave absolute paths unchanged.
- **Keep the `--var-file` CLI flag cwd-relative.** `cmd_cloud_tf.ml:1667` defines `--var-file`, and when it's given it replaces the target's key (`match var_file with Some _ -> var_file | None -> config_var_file`, around line 1000). Today both go through the same `normalize_var_file`. A path typed on the command line is conventionally relative to the shell, so it stays cwd-relative. Resolve the two separately, before they are merged, so the rule depends on where the path came from.
- Document the rule where `terraform_var_file` is documented (`contract/substrate.md` or its successor under `docs/reference/`).

## Acceptance criteria

- A test runs from a *subdirectory* of a workspace and shows that a target's relative `terraform_var_file` resolves to `<workspace-root>/<path>`, and that an absolute path passes through unchanged.
- A test shows a relative `--var-file` still resolves against the invocation directory.
