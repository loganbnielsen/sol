Make `sol.toml` the single, required source of a `-fn` schedule, key Pushgateway metrics by workload, and actually push them

**Depends on:** None.

**Finding:** FND-0034 (`internal/pipeline/audits/findings/`).

**Premise verified 2026-09-23** against `origin/main @ f3e9480b` while filing (see the finding).

## Problem

`extract_schedule` defaults an absent `schedule` to hourly; `Fn.Cron "<cron>"` in code is a second schedule the runtime never uses except as the default Pushgateway `job` name (two functions with one schedule would overwrite each other's group); generated `-fn` mains never pass `~pushgateway_url`, so `sol_fn_invocations_total` never leaves the process (EXP-022, still live).

## Remediation

Require `[service] schedule` for `-fn` (plan error naming the file when absent; remove the hourly default and the duplicate re-read — use the plan's loaded `toml`). Change `Fn.trigger` to carry no schedule string (`Cron | Lambda`). Default the Pushgateway job to the workload identity (`<domain>/<name>`, via an env var the manifest renders). Have `Fn.Make.run` read `PUSHGATEWAY_URL` when `?pushgateway_url` is omitted, and update the scaffold. This subsumes EXP-022 — move EXP-022 to DONE in the same PR with a pointer here.

## Acceptance criteria

- A `-fn` with no `schedule` fails `sol plan`/`deploy` with a message naming the `sol.toml`.
- Two generated `-fn`s push to distinct Pushgateway groups (test on the job-name derivation).
- A generated `-fn` with `PUSHGATEWAY_URL` set pushes after a run (test with a stub endpoint).
- `TUTORIAL.md:520` no longer says the schedule is read from source.
- Demo/example: the scaffolded `-fn` and any example `-fn` are updated (author-facing change).
- TS parity: record verdict for TS scheduled functions.
