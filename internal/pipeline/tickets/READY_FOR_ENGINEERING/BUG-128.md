title: soldev cannot submit or merge a filing PR whose new ticket declares a dependency
source: filing INFRA-100 after SEC-011 (observed)

**Depends on:** None.

## Problem

The ticket workflow is "file first, implement second": a finding is filed in
`BACKLOG/` or `READY_FOR_ENGINEERING/` on its own filing PR, and the
implementation PR later moves it to `DONE/`. A filing often declares a
dependency on the ticket that must land first (`**Depends on:** SEC-011.`), which
`soldev pipeline check` correctly reports as `blocked-by-dependency` — that part
works.

`soldev` cannot land such a filing PR. Both of its merge paths refuse it, because
a PR whose branch names ticket `T` is modelled as "the implementation PR for
`T`":

- `soldev pipeline submit <T>` requires the ticket to be in `DONE/` on the
  branch, which a filing PR does not and must not do, so the filing PR has to be
  opened by hand (`git push` + `gh pr create`).
- `soldev pipeline merge <T>` and `soldev pipeline merge --pr <n>` both refuse
  with `ticket prerequisites unresolved — skipping`, because the filing ticket's
  own dependency is not `DONE` yet. The filing does not implement the ticket, so
  its prerequisites are not a merge condition.

So the only way to land a filing PR with a forward dependency is a raw
`gh pr merge --squash --auto` — which skips exactly the head-pin and
prerequisite checks `soldev` exists to apply, i.e. the workaround defeats the
guardrail.

## Reproduction (2026-10-03)

On branch `INFRA-100/qualification-runner-image`, whose only change is adding
`internal/pipeline/tickets/READY_FOR_ENGINEERING/INFRA-100.md` with
`**Depends on:** SEC-011.` (SEC-011 was `READY_FOR_ENGINEERING` at the time):

```
$ soldev pipeline submit INFRA-100
error: internal/pipeline/tickets/DONE/INFRA-100.md not found. Run this from the ticket's
worktree, after your final commit has already moved the ticket file to DONE/ on this branch.

$ gh pr create --base main ...            # the only way to open it
https://github.com/loganbnielsen/sol/pull/1004

$ soldev pipeline merge INFRA-100
error: nothing was queued: the pull request was skipped, and the message above says why.
  ticket prerequisites unresolved — skipping (https://github.com/loganbnielsen/sol/pull/1004)

$ soldev pipeline merge --pr 1004
  ticket prerequisites unresolved — skipping (https://github.com/loganbnielsen/sol/pull/1004)
```

The same shape will recur for any filing that depends on work still in flight,
which the audit/filing flow produces routinely.

## Remediation

Distinguish a **filing** PR from an **implementation** PR, and apply the two
gates only to the second:

- `pipeline submit` should not require a `DONE/` move when the ticket *does not
  exist at the base* (it is newly added by this branch) — the same
  base-existence test the ticket-move guard already uses
  (`internal/ci/context/check_ticket_move.sh`, `git cat-file -e
  "$BASE:$root/READY_FOR_ENGINEERING/$upper.md"`), so the two agree on what a
  filing is.
- `pipeline merge` should not treat a ticket's prerequisites as unresolved when
  the branch does not carry the ticket to `DONE/`. The prerequisite gate exists
  so an implementation does not land before what it depends on; a PR that only
  files the ticket is not that.

## Acceptance criteria

- A PR that adds a new ticket to `READY_FOR_ENGINEERING/` (or `BACKLOG/`) with a
  dependency can be submitted and queued for squash auto-merge with `soldev`
  alone, with no raw `gh pr merge`.
- An implementation PR that moves a `READY_FOR_ENGINEERING` ticket to `DONE/` is
  still refused while its declared dependencies are not in `DONE/`.
- The mutation/dry-run coverage for `pipeline merge`'s prerequisite gate gains
  the filing case, so the distinction cannot regress.

tooling, no app-author surface.
