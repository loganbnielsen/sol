`sol-svc`: deliver an external `stop` to the server, and reject a malformed `PORT`

**Depends on:** None.

**Finding:** FND-0041 (`internal/pipeline/audits/findings/`).

**Premise verified 2026-09-23** against `origin/main @ f3e9480b` while filing (see the finding for the command/probe and observed output).

## Problem

`Service.Make.run` passes only the signal promise to `Cohttp_eio.Server.run ~stop`; an external `?stop` keeps the server accepting for the full `drain_timeout_s`, then reports "drain timeout reached" (observed: 3.00s with nothing in flight). A non-integer `PORT` silently falls back to the default (observed with `80800x`, `tcp://…`).

## Remediation

Resolve the server's stop from either signal or external stop; return `Error (`Config …)` for an unparsable `PORT`. The preStop/readiness-flip gap (FND-0041 c) is out of scope here.

## Acceptance criteria

- With `~drain_timeout_s:3.0` and an external stop resolved at listen, `run` returns well under 3s without the drain-timeout message (test uses a non-trivial timeout, not 0.1).
- `PORT=abc` makes `run` return `Error (`Config _)` naming the value.
- TS parity: check the TS svc shutdown/PORT handling and record a verdict.
- Demo/example: not applicable — state in completion notes.
