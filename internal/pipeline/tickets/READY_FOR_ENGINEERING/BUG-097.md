Honour shutdown in Retry_topics workers instead of waiting for SIGKILL

**Depends on:** None.

**Premise verified (2026-09-29):** At `origin/main` `7f6aa377`, `Kafka_service.consume_partitioned` accepts `?stop`, but its `Retry_topics` branch (`framework/ocaml/kafka-eio-service/lib/kafka_service.ml:445-455`) does not forward it. `Kafka_service_retry_topics.consume` has no stop parameter. `sol-worker` passes `~stop:stop_handle` (`framework/ocaml/sol-worker/lib/worker.ml`, `Make_with_retry_and_test_seam`), and only the `In_memory` branch uses it.

## Problem

`Retry_topics` is the documented production retry strategy, yet a worker using it does not stop on SIGTERM, SIGINT, or a caller `stop`:

- The source and retry consumers run `consume_partitioned` without `?stop`. Shutdown is noticed only when the handler's `should_stop ()` check runs, which happens only when a record arrives.
- An idle source topic therefore never stops.
- Even when a source record triggers `Stop`, the retry relay (`Eio.Fiber.fork ~sw` in `kafka_service_retry_topics.ml:503`) runs on the runtime's outer switch. It keeps that switch open until a retry record also arrives.

Rendered pods have `terminationGracePeriodSeconds: 45`. Every rollout, scale-down, and node drain of a `Retry_topics` worker therefore takes the full grace period and ends in SIGKILL. `Sol_obs.flush`, which runs after `with_runtime` returns, never runs, so buffered logs and traces from the shutdown window are lost. Any handler still in flight is killed rather than drained.

The existing stop tests use `?test_consume_loop`, which bypasses the real consumers. That is why this passes CI.

**Reproduction** (scratch executable against local Redpanda and the pinned libraries): `Worker.Make_with_retry` with an idle topic, with the caller `stop` resolved 3s after `on_ready`.

- `In_memory` control: `run returned Ok` 0.0s after stop.
- `Retry_topics`: `run did NOT return` when the harness gave up 22s after stop.

## Remediation

Thread the stop promise through `Kafka_service_retry_topics.consume` into both the source and the relay `consume_partitioned` calls. Make the relay's lifetime end with the source's: stop and join it when the source consumer returns, on any exit path. Keep BUG-043's relay-failure semantics.

## Acceptance criteria

- A broker-backed test: an idle `Retry_topics` worker returns promptly after `stop`, with both consumers closed and no fiber left on the caller's switch.
- The same holds with records flowing on the source topic and an empty retry topic, and vice versa.
- SIGTERM reaches the same path in a `sol-worker` binary, and `Sol_obs.flush` runs.
- Record the TypeScript worker shutdown parity verdict in completion notes.
