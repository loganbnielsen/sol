`sol.toml` must reject unknown keys and tables, as `sol.yml` already does

**Depends on:** None.

**Finding:** FND-0033 (`internal/pipeline/audits/findings/`).

**Premise verified 2026-09-23** against `origin/main @ f3e9480b` while filing (see the finding for the command/probe and observed output).

## Problem

`Sol_cli_toml.load_result` reads known paths only; `[infra.scale] replica = 3`, `[infra.sacle]`, `[infra.rolout]` all load as `Ok` with the setting dropped (probe in FND-0033). The "forward-compatible" rationale is void under the pre-alpha no-compat policy, and `sol.yml` is already fail-loud (FEAT-025/028).

## Remediation

After reading known keys, walk the document and reject any key/table not in the schema for its section, naming key and file.

## Acceptance criteria

- Each typo case from FND-0033 returns `Error` naming the unknown key and the file.
- Every scaffolded `sol.toml` (all templates in `sol_cli_scaffold_templates.ml`) and every `sol.toml` under `examples/` and `internal/fixtures/` still loads.
- Demo/example: examples must still load; state that in completion notes.
- TS parity: `sol.toml` is language-neutral CLI config — no language-parity impact.
