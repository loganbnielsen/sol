title: Rollback re-renders an OCaml service with the TypeScript readiness probe
source: rollback fidelity qualification 2026-10-02 (repository-derived + modelled-cluster run)

**Depends on:** None.

Rollback restores a release by reconstructing each workload's spec from the
release record and re-rendering it. The record never captured the workload's
language, so `Sol_cli_rollback.decode_workload` sets `language = None` and
`Sol_cli_deployment_render.render_spec` derives the readiness probe from it:

```ocaml
readiness_path =
  (match s.language with
   | Some Sol_cli_compat.Ocaml -> "/readyz"
   | Some Sol_cli_compat.Typescript | None -> "/healthz")
```

Every OCaml service is therefore re-applied with `readinessProbe.path:
/healthz` instead of the `/readyz` it was deployed with, while the
`startupProbe`/`livenessProbe` stay on `/healthz`. TypeScript services are
unaffected because their readiness path is `/healthz` either way.

## Impact

Rollback is supposed to restore the recorded release boundary faithfully. For
an OCaml `-svc` it does not: the restored workload is not the artifact that was
deployed. `/readyz` turns 503 as soon as shutdown begins so the endpoint
controller drains the pod before it stops accepting; `/healthz` stays 200, so a
rolled-back pod keeps receiving traffic while it drains. The restore silently
weakens the shutdown semantics of the release it claims to have restored.

The existing reconstruction gate does not catch this: every fixture in
`cli/test/inline/test_rollback.ml` sets `language = None`, so the
"render correctness" comparison (original bytes vs reconstructed bytes) is
comparing `None` against `None` and cannot distinguish the two paths.

## Remediation

1. Record the workload language in the release record: add
   `language : string option` to `Sol_cli_release_id.workload`, encode/decode it
   in the record JSON, and populate it in
   `Sol_cli_deployment_plan.release_workload_of_spec`.
2. Extend the canonical identity encoding with the language only when it is
   present, so a record written before this change (which has no language and
   genuinely knows none) still rederives the id it recorded. Do not bump
   `encoding_version`: the existing bytes are unchanged, so no deployed release
   record becomes unreadable.
3. Parse it back in `Sol_cli_rollback.decode_workload`, failing closed on an
   unknown value, and set `service_spec.language` instead of `None`.
4. Regression: an OCaml spec's reconstruction must render byte-identically to
   the original deploy render (the existing gate, with a `language = Some Ocaml`
   fixture instead of `None`), and the language must round-trip through the
   record JSON.

## Acceptance criteria

- A release built from a spec with `language = Some Ocaml` reconstructs with
  `language = Some Ocaml`, and its reconstructed render is byte-identical to the
  original deploy render (readinessProbe on `/readyz`).
- A record carrying no language still reconstructs (as `None`) and still
  rederives the id it was stored with.
- The record JSON round-trips the language field.
- `soldev pipeline validate` passes; the rollback suite is green.
- Demo/example: no example change. Rollback is not exercised by a runnable demo
  (the examples deploy fresh); the regression is the reconstruction gate.
- Language parity: OCaml-only. The TypeScript scaffold serves `/healthz` as
  both liveness and readiness, so no TypeScript-side change is needed and the
  reconstructed TS render is unchanged.

## Completion notes

- Fixed in this branch. The language is recorded in the release record JSON
  (`workload_to_json` emits it only when set, so a record written before this
  change serializes and digests identically), carried in
  `release_workload_of_spec`, extended into the identity encoding only when
  present, and parsed back strictly in `decode_workload`.
- `encoding_version` is deliberately not bumped: the existing known vectors
  (`r-9255cab6aa649011` in `test_release_id`, `d14c45499af5cc91ec0a6c3250801cfa`
  in `test_release`) still pass unchanged, so no deployed release record becomes
  unreadable. New tests pin a language-bearing known vector
  (`r-8caeacc6de9875ac`) and assert that a language-less record adds nothing to
  the encoding.
- Verification: `dune build`; `dune test cli/test/inline` (green, including the
  new reconstruction gate, the JSON round-trip, and the three modelled-cluster
  qualification cases); `internal/ci/check_ocamlformat.sh --staged`.
- Evidence and the open follow-ups (BUG-119, BUG-120, BUG-121) are in
  `internal/pipeline/audits/2026-10-02_rollback_fidelity_qualification.md`. That
  run is modelled-cluster, not live; a live rollback row remains unqualified
  because this environment has no container runtime.
