Own one migration-directory contract in pg-eio, and roll back by recorded file identity

**Depends on:** None.

**Premise verified (2026-09-29):** At `origin/main` `7f6aa377` with `pg-eio` pinned at `1cfc9b51`:

- `pg-eio` `lib/migration.ml:11-35` parses migration file names and silently drops any `.sql` file it cannot parse.
- Sol re-implements the same grammar strictly in `cli/lib/base/sol_cli_migration.ml:20-101`, and every `sol migrate` path calls it first (`cmd_migrate.ml:183`) to compensate.
- `Migration.rollback` rebuilds the down file name as `%04d_<name>.down.sql` (`migration.ml:316`).
- Sol's own error text recommends `001_create_orders.sql`.
- `sol migrate apply --dry-run` prints every migration file, not the pending ones (`cmd_migrate.ml:60-81`).

## Problem

- **Rollback cannot find down files it should.** A migration named as Sol recommends (`001_create_orders.sql`, `001_create_orders.down.sql`) is recorded as version 1, `create_orders`. Rollback then looks for `0001_create_orders.down.sql` and fails. The same happens for any width other than 4.
- **Two grammars for one contract.** The library that applies migrations silently skips files the CLI would reject, so correctness depends on every caller remembering to run Sol's validator first. Any other `pg-eio` consumer, or a new Sol path, gets the lax behavior.
- **`--dry-run` shows the wrong SQL.** The output is labelled pending, but applied migrations are included.

## Remediation

Make `pg-eio` own the strict directory contract: an unparseable or duplicate-version `.sql` file is an error. Expose the parsed migration list, and have Sol use it instead of its own parser. Rollback resolves the down file from the same parsed identity (the up file's actual name), never by reformatting the version. Dry-run prints exactly the migrations `apply` would run, which requires a database read of applied versions. Update the pin and Sol's call sites in the same pass.

## Acceptance criteria

- `001_x.sql`/`001_x.down.sql` and `0001_x.sql`/`0001_x.down.sql` both roll back.
- `pg-eio` `apply` refuses a directory containing an unparseable `.sql` file, and Sol has no second parser.
- `--dry-run` against a database with some applied migrations prints only the pending ones.
- Update a runnable migration example. No application-language parity impact (migrations are CLI/library tooling).
