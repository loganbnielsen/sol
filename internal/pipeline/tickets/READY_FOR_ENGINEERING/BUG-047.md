Install the SIGTERM/SIGINT handler once per process and restore default disposition after the first signal

**Depends on:** None.

**Finding:** FND-0042 (`internal/pipeline/audits/findings/`).

**Premise verified 2026-09-23** against `origin/main @ f3e9480b` while filing (see the finding for the command/probe and observed output).

## Problem

`Sol_runtime.install_signal_handler` is called by every primitive's `run`; `Sys.set_signal` is process-global, so the last install wins and co-hosted primitives never drain. The handler outlives the pipe it writes to (fd may be reused) and swallows a second signal.

## Remediation

One lazily-installed process handler that resolves all registered stop promises; `run` registers/unregisters. After the first signal, restore default disposition so a second one terminates.

## Acceptance criteria

- Test: two registered promises are both resolved by one SIGTERM.
- Test: after the handler's switch ends, a signal does not write to the old fd.
- Demo/example: the local demo (svc+worker+jobs in one process) drains all three — note in completion notes.
