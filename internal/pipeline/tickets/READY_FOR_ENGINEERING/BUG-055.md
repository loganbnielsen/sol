`Kafka_service.config_of_env`: require `KAFKA_BROKERS`, `SCHEMA_REGISTRY_URL` and `REDPANDA_ADMIN_URL` instead of defaulting to localhost

**Depends on:** SEC-007.

**Finding:** FND-0054 (`internal/pipeline/audits/findings/`).

**Premise verified 2026-09-24** against `origin/main @ fd5c7e0c`
(`kafka_service_config.ml:2-25` defaults all three).

## Problem

An unset address becomes localhost. In a pod nothing listens there, so an overlay or
external-substrate config that omits one fails later, with an error naming localhost
instead of the missing variable.

## Remediation

Return an `Error` naming each missing variable, as SEC-007 did for
`KAFKA_SECURITY_PROTOCOL`. Update everything that relies on the defaults: fixture and
example run commands, `run_tests.sh`, the e2e skill, and the tutorial's local tables.
`sol local run` and rendered manifests already set all three.

## Acceptance criteria

- Test: each unset variable is an `Error` naming it.
- Documented local commands set all three.
- Demo/example: the local demo and example run commands set them.
- TS parity: record the verdict (DEC-022).
