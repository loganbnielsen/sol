**Depends on:** None.

## The defect

`docs/architecture/observability-design.md` states that every log line, metric,
trace, deploy event and dashboard link carries the same six-label identity —
`workspace`, `env`, `domain`, `service`, `primitive`, `release` — and its
Identity section says explicitly "all six labels, including `env`, are emitted
(OBS-008, `env` added by FEAT-026)". `env` reaches two of the three signals:

- **Pod labels:** the manifest renders `env` when a target resolves one
  (`cli/lib/workspace/sol_cli_manifest_yaml.ml`'s `taxonomy_labels ?env`).
- **Metrics:** the pinned `prometheus-community/prometheus` chart's
  `kubernetes-pods` job applies `labelmap __meta_kubernetes_pod_label_(.+)`, so
  `env` becomes a metric label.
- **Logs:** the Alloy promotion list omits it, so `env` is never a Loki stream
  label. The list is written twice and both are missing `env`:
  - `platform/cloud/modules/platform/main.tf`:
    `observability_taxonomy_labels = ["workspace", "domain", "service", "primitive", "release"]`
  - `cli/lib/local/sol_cli_dev_observability.ml`:
    `~taxonomy_labels:[ "workspace"; "domain"; "service"; "primitive"; "release" ]`

Because the two lists are hand-copied, "dev mirrors prod" cannot be relied on
for this set either.

## Impact

A LogQL query that filters on `env` (a prod-only log view, or a
`--target`-scoped investigation) returns nothing even though the same series
exists in Prometheus, and the documented identity contract is false for logs.
The local run observed the app-pushed stream labels
(`{"service":"order-svc","service_name":"order-svc"}`) and read the promotion
lists from the artifacts that own them; the deployed end-to-end effect is
mechanism-level until a cluster is scraped (see the matrix, OB-L3).

## Remediation

1. Add `"env"` to `local.observability_taxonomy_labels` in
   `platform/cloud/modules/platform/main.tf`.
2. Add `"env"` to the mirror in `cli/lib/local/sol_cli_dev_observability.ml`'s
   `alloy_values_yaml`.
3. Add a guard that keeps the two lists identical and ties the log promotion
   set to the manifest taxonomy (`taxonomy_labels` in
   `sol_cli_manifest_yaml.ml`), so a future seventh label cannot be added to
   one place only. The guard reads the Terraform structurally (Python +
   `tfconfig.py`, per the CI rule) rather than grepping its text, and its
   mutation test must fail it for the reason under test.
4. Leave the manifests' optional `env` alone: `sol up`/local genuinely has no
   environment, and an absent pod label sets no stream label.

## Acceptance criteria

1. Both promotion lists carry `env`.
2. The guard fails if either list drifts from the other, or if the log
   promotion set stops covering the manifest's taxonomy labels.
3. A mutation that drops `env` from one list fails the guard.

## Demo/example

The scaffold/example manifests already render `env` for a target; no example
file changes. The completion note records that the generated Alloy config now
promotes it (visible by rendering `Sol_cli_dev_observability.alloy_values_yaml`
in a test).

## Language parity

The identity vocabulary is a cross-language convention (DEC-022). The TypeScript
framework's log shipping must carry the same six labels; check the TS scaffold
and record the verdict in the completion note.
