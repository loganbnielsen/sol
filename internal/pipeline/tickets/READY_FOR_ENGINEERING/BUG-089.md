Keep cross-domain caller ingress when deploying a callee alone

**Depends on:** None.

**Premise verified (2026-09-29):** At `origin/main` `2485a3af`, `sol_cli_deployment_plan.ml:903-930` derives `called_by` only from selected `resolved_services`; `sol_cli_deployment_render.ml:153-166` and `sol_cli_manifest_yaml.ml:605-654` render those edges as cross-namespace ingress rules. DEC-036 confirms target resolution uses the full inventory while scope stays narrow.

## Problem

Deploying only a callee excludes its unselected cross-domain caller from `called_by` and replaces the callee's NetworkPolicy without that ingress rule. The caller remains running, but its requests to the callee are denied by network policy. A full-workspace plan includes the edge; existing tests exercise only that case.

## Remediation

Derive incoming call edges from all declared workspace callers while keeping the rendered/deployed workload set limited to the requested scope. Preserve the existing rejection of calls to nonexistent targets.

## Acceptance criteria

- Render a callee-only scoped plan with a caller in another domain; its NetworkPolicy retains the caller namespace and pod selector, while the plan still deploys only the callee.
- A full plan renders the same ingress edge, and a misspelled call target fails closed.
- Verify the network-policy document emitted by the command path, not only the `called_by` list. Update a runnable cross-domain scoped-deploy example and record the per-language verdict.
