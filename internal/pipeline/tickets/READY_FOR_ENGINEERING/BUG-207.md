**Depends on:** None.

## Premise verified

`cli/lib/cloud/sol_cli_cloud_wiring.ml` removes bootstrap access after an install attempt, including failure. The AWS retry ran as steady-state `cluster-access` and was forbidden from platform RBAC mutations. GCP also removed access after its failed install. The GCP retry outcome has not been observed. Under DEC-034 the AWS cloud provisioner intentionally has no cluster access entry; bootstrap admin is temporarily associated with the separate cluster-access principal. Therefore the missing provisioner entry and its Unauthorized kubeconfig do not demonstrate a broken acquisition path. Current cloud apply already plans `provisioner_bootstrap_admin=true`; the exact retry command and effective grant must be traced before changing this logic. The failed objects are in `default` and `kube-system`, outside the steady-state platform namespace bindings.

## Remediation

Trace the observed retry entry point and bracket acquisition, including the principal carrying the temporary grant, plan precedence and effective-access propagation. Make the supported retry reopen and verify the temporary install window before reconciling an incomplete platform, with removal on every exit. Preserve the steady-state access boundary; do not grant permanent installation rights to `cluster-access` or `operator`. Surface the original platform failure and the retry procedure separately from an authorization failure.

## Acceptance criteria

- Simulate an install failure, verify the temporary grant is removed, retry, and observe a bounded grant restored for reconciliation and removed again after success or failure.
- Test AWS and GCP lifecycle paths and a post-failure destroy.
- Example impact: none; this repairs internal cloud lifecycle. Language-parity impact: none; both languages share it.
