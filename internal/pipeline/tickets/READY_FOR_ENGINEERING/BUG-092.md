Align scoped release provenance and commit rollback with the recorded boundary

**Depends on:** None.

**Premise verified (2026-09-29):** At `origin/main` `50672938`, both apply paths render the selected plan's `release_id`, while `Sol_cli_release.of_plan_with_boundary` records the derived boundary ID as the selected workload's `applied_by`. `Sol_cli_release_id.of_boundary` uses a separate encoding when it inherits a workload. Deployment events keep the plan ID, and `--commit` uses it to fetch a release record. The audit traces every caller and the positive control.

## Problem

After a successful scoped deploy with inherited workloads, the current release record claims its newly applied workload carries the boundary ID, while the live manifest carries the plan ID. Live verification reports drift for the release just applied. Commit-based rollback resolves the plan ID from the deployment event but the persisted complete release has the boundary ID, so it cannot find the record.

## Remediation

Represent the applied deploy identity and complete boundary identity consistently through render, record, verification, and deployment-event resolution. Preserve a content-derived immutable boundary ID, record each workload's actual live provenance, and ensure a successful deployment event resolves to the persisted complete boundary. Do not make `--commit` guess from the selected plan ID.

## Acceptance criteria

- A full A+B deploy followed by scoped A update produces a complete record whose A and B provenance matches the live manifests exactly; verifying that record reports no mismatch.
- `sol rollback --commit <scoped-deploy-commit> --scope A` resolves the persisted complete boundary and restores it. A first/full deploy remains compatible with its own plan ID.
- Regression tests exercise selected-plan construction, real manifest rendering, release recording, and commit resolution; tests constructed only from a prefilled release record are insufficient.
- Update a runnable scoped deploy/rollback example and record the per-language verdict in completion notes.
