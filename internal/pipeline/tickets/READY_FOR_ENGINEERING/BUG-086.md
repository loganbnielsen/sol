Pass target location to GCP node-pool and Cloud NAT inventory checks

**Depends on:** None.

**Premise verified (2026-09-29):** At `3f662e7b`, traced `Sol_cli_gcp_absence.checks` and ran the installed `gcloud` commands with `--project=probe --quiet` and no credentials. `container node-pools list` refused with `One of [--location, --zone, --region] must be supplied`; `compute routers nats list` refused with `Underspecified resource ... Specify the [--router-region] flag`.

## Problem

The GCP inventory receives `target.region` but omits it from the node-pool and Cloud NAT commands. Both location-scoped commands fail before reaching the provider unless the operator has configured a matching default region. A different configured default can also query the wrong location. The failures become `Unobservable`, preventing a complete independent absence verdict and hiding recoverable resources from reconciliation.

## Recommended direction

Supply the target's region/location explicitly on every location-scoped provider command. Keep the location derived from the resolved target, not the user's mutable gcloud configuration.

## Acceptance criteria

- Node-pool and Cloud NAT checks pass explicit target location flags accepted by the installed `gcloud` commands.
- Tests inspect/execute the generated argv with no configured default region and show the target region wins over a conflicting default; failure remains `Unobservable`.
- A successful empty result and a present result retain their existing classification, and the acceptance covers both affected resource classes.
- Completion notes explain why an app-author demo and language-parity change are not applicable to this cloud safety correction.
