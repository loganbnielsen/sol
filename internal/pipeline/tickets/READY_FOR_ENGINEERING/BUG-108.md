**Depends on:** None.

## Problem

BUG-105's contract reconciliation takes a workspace *root*, but `sol up` passed the workspace *name* — the `name` that `Sol_cli_workspace.enter_cwd` returns beside `root` — and `sol deploy` passed `ctx.execution.workspace`, also a name. `Sol_cli_contract.has_projection` then tested `<name>/contract` relative to the working directory, which does not exist, so reconciliation was silently skipped and the deploy succeeded without registering anything.

The consequence is the exact failure that motivates BUG-105, one step later: a scaffolded `charge_svc` producer starts read-only against an empty subject and crash-loops. `golden-path-smoke` (run `36783691812`, step 11) caught it: `charge_svc rollout failed — CrashLoopBackOff`, 800s of back-off.

## Remediation

Pass the workspace root, which is an absolute path in both call sites:

- `sol up` uses `repo_root` (the `root` from `Sol_cli_workspace.enter_cwd`).
- `sol deploy` uses `ctx.facts.Sol_cli_workspace_model.root`.

## Acceptance criteria

- `sol up` reconciles the declared contract for a scaffolded workspace before applying any workload, and `golden-path-smoke` passes.
- `sol deploy` reconciles from the workspace root.

**Demo/example coverage:** no example change; the golden-path smoke is the regression guard for this shape of mistake.

## Completion notes (2026-09-30)

Both call sites now pass the absolute workspace root. `golden-path-smoke` on this PR is the verification: it scaffolds a workspace, deploys it, and fails if a producer cannot resolve its contract.
