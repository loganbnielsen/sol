A stopped Retry_topics relay must fail the worker, not wait for the source consumer to exit

**Depends on:** None.

**Finding:** FND-0035 (`internal/pipeline/audits/findings/`).

**Premise verified 2026-09-23** against `origin/main @ f3e9480b` while filing (see the finding for the command/probe and observed output).

## Problem

The relay fiber in `Kafka_service_retry_topics.consume` records `relay_failure` and returns; the ref is read only after the source consumer returns, which a healthy consumer never does. Health stays green while retry delivery is suspended indefinitely. BUG-029 deferred this explicitly.

## Remediation

When the relay stops with an error, stop the source consumer (resolve its stop / fail the switch) so `consume_partitioned` returns `Error` promptly; or fail `/livez` from relay state.

## Acceptance criteria

- A test where the relay's `consume_partitioned` fails while the source topic is idle observes `consume_partitioned` returning `Error` within a bounded time.
- `sol-worker.md` / `kafka-eio-service.md` exhaustion-policy text updated to match.
- TS parity: record whether `@sol-fab/worker` has the same relay shape (verdict or tracking ticket) in completion notes.
- Demo/example: not applicable (framework internals) — state in completion notes.
