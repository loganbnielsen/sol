The representative consumer is not idempotent for its domain write under duplicate fact delivery

**Depends on:** None.

## Problem

The outbox contract is explicitly at-least-once: a duplicate fact is a legal outcome, and
consumers must tolerate it. `FEAT-120`'s run delivered the same `Charged` domain event
(`q-baseline`) twice and observed:

```text
pluto_notifications = 2      (a second row for the same charge)
sol_jobs            = 1      (the independent effect was deduped by ~dedupe_key)
```

So the *independent effect* is idempotent, but the consumer's own domain insert is not: a
redelivered fact duplicates the notification. The example is the checked-in demonstration of
the architecture Sol recommends, and it does not demonstrate the consumer half of the contract
it documents.

`examples/pluto/app/comms/notify_worker/lib/notify_worker.ml` inserts with
`Notification.insert tx ...` (a plain `INSERT`) and relies on the job's `~dedupe_key` alone.

## Remediation

Make the consumer's domain write idempotent for the delivered fact, so a redelivery of the same
event does not duplicate it — for example an `ON CONFLICT DO NOTHING` on a natural key, or a
version/`event id` guard — and show in the example that a duplicate delivery is absorbed. Keep
the job's `~dedupe_key`, which already holds. Do not weaken the outbox contract to avoid
duplicates; the contract accepts them and the consumer must tolerate them.

## Acceptance criteria

- Delivering the same fact twice leaves exactly one domain row and one independent effect, and
  the fact itself is still acknowledged.
- The example's migration and `lib/notification.ml` carry whatever key the guard needs.
- The runnable example (or the tutorial's worker section) shows the guard, so an app author sees
  how a duplicate is absorbed.
- `FEAT-120`'s record is updated to cite the fixed behaviour on its next run.

**TypeScript parity (DEC-022):** check the TypeScript demo's consumer against the same
duplicate-delivery expectation and record the verdict or a tracking ticket.
