**Depends on:** None.

**Related:** `OBS-050` (the trace gap this resolves), `OBS-008` (the label taxonomy),
`OBS-039` (Alloy), `OBS-041`/`OBS-042` (tracing), `DEC-022` (language parity),
`docs/architecture/observability-design.md` §Identity.

## Question

Every log line, metric and trace is supposed to carry Sol's semantic workload
identity — `workspace`, `env`, `domain`, `service`, `primitive`, `release`. Logs
and metrics get it from a collector promoting the pod labels Sol renders. **A
trace is pushed by the application over OTLP, and no Sol collector enriches
it.** So which side owns the trace's resource identity: Sol's instrumentation, or
a collector?

## Decision (operator, 2026-10-02)

> **Sol framework/runtime instrumentation emits Sol's semantic workload identity
> on every signal it produces. Collectors may independently enrich infrastructure
> identity, but they never define or replace Sol's semantic vocabulary.**

The split is by *whose fact it is*:

| Identity | Owner | Examples |
|---|---|---|
| Semantic workload identity | Sol instrumentation (framework/runtime) | `workspace`, `env`, `domain`, `service`, `primitive`, `release` |
| Infrastructure identity | The collector / platform, additively | `namespace`, `pod`, `node`, `host`, cloud region — k8s/OTel-conventional names |

## Why — verified against the architecture (2026-10-02, `main @ 3d29d043`)

- **Logs** already get the taxonomy from Alloy promoting the rendered pod labels
  (`platform/shared/observability/alloy/logs.alloy.tftpl` + `local.observability_taxonomy_labels`),
  and **metrics** from the pinned `prometheus-community/prometheus` chart's
  `kubernetes-pods` job applying `labelmap __meta_kubernetes_pod_label_(.+)` over
  the same pod labels. Both are collector enrichment of labels Sol rendered.
- **Traces get nothing.** `obs-tempo-eio`'s `resource_attributes ~service context`
  emits `service.name` plus whatever the application passed as `~context`; there
  is no collector in the trace path, and no enrichment step.
- **`external` mode has no Sol collector at all** — logs are shipped by Alloy or
  the SDK and traces go straight to the user's endpoint. A collector-owned
  identity would simply be absent there.
- **The vocabulary is Sol's own.** A generic collector cannot know a release id,
  or that `domain` means a team-owned vertical. Conversely, `namespace`/`pod`/
  `node` are environment facts the application does not own and should not fake.
- The design doc already says Sol owns "the telemetry label and attribute
  vocabulary" (`observability-design.md` §What Sol owns, what Grafana owns).

## Consequences

1. The manifest injects the semantic identity as environment variables — the
   same values it already renders as pod labels — so an app can read them at
   runtime.
2. `Sol_obs.of_env` composes them into the context it already threads to Loki
   stream labels and OTLP resource attributes (the mechanism exists;
   `obs-tempo-eio` maps context pairs to resource attributes).
3. **The values must be identical across signals.** Observed 2026-10-02 with a
   rendered scaffolded workspace: the app's `~service` is
   `<workspace>-<unit>-<primitive>` (`obsdemo-charge-svc`) while the rendered pod
   label `service` is the bare Kubernetes name (`charge-svc`). So app-emitted
   traces and direct-pushed logs disagree with the collector-promoted logs and
   metrics about the same workload. Aligning this is part of `OBS-050`.
4. Metrics emitted by the framework must agree with the scrape labels. If
   `obs-prometheus-eio` has no const-label capability today, that is an
   implementation gap for `OBS-050` — not a licence for the collector to own the
   semantic vocabulary.
5. Collector enrichment stays additive and namespaced (k8s/OTel conventions);
   it never reuses a Sol label name for an infrastructure fact.

## Non-goals

- Sol does not have to deploy or configure a trace collector for this contract;
  the framework path stands alone.
- No renaming of the OTel `service.name` fallback used by non-Sol SDKs.
- No requirement that infrastructure identity be present; it is enrichment, not
  part of the contract.
