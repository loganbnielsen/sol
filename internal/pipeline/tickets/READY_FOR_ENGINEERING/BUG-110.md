**Depends on:** None.

`docs/reference/cli.md` is generated from the binary's own help, and
`internal/ci/check_cli_reference.py` fails when the page and the binary disagree — an undocumented
command, a command the binary does not register, or a flag a command does not have.

**The guard did not run on the path where the drift can enter.** The classifier treated a change to
`docs/reference/cli.md` as `docs-only`, and the docs-only fast path deliberately skips every guard.
Run rather than reasoned — the script takes a file list, not a path, and an unknown argument makes it
emit `source`:

```text
$ printf 'docs/reference/cli.md\n' > /tmp/paths
$ internal/ci/classify-changes.sh --files-from /tmp/paths
docs-only

$ printf 'cli/bin/main.ml\n' > /tmp/paths          # positive control
$ internal/ci/classify-changes.sh --files-from /tmp/paths
source
```

The rule was the classifier's own fall-through, where `docs/*` and `*.md` both mean prose, and the
guard that would catch a hand-edited command row ran only on the other path:

```text
$ grep -n -A 2 check_cli_reference .github/workflows/ci.yml
701-        if: needs.classify.outputs.kind != 'docs-only' || steps.docs_tooling.outputs.cache-hit != 'true'
702:        run: python3 internal/ci/check_cli_reference.py
```

So a PR that edited a command row — the one drift the guard exists to catch — took the fast path,
where the guard, its mutation test and the product build were all skipped. The fast path restores
only a cached *soldev* binary, so the guard could not simply be added there: there is no
`cli/bin/main.exe` for it to read.

## Status

**Already fixed** — the change landed in PR #784 and is on `main`. This ticket is filed so the
record can move to `DONE` through the normal path: the fix merged under the id `BUG-108`, which
another fix concurrently claimed and then replaced, leaving the classifier change undocumented in
the ticket tree. The evidence and completion notes below are the record; there is no work left here.

## Remediation

Classify the generated page as an artefact of the code rather than as prose: `classify-changes.sh`
keeps a list of generated artefacts — one entry today, `docs/reference/cli.md` — and routes a path on
that list to `source` before the prose allowlist is consulted.

## Completion notes (2026-09-30)

Landed in PR #784. Verified by running both classifiers on the same file list, before and after, with
the prose control in the same directory:

```text
$ printf 'docs/reference/cli.md\n' > /tmp/paths
$ git show <before>:internal/ci/classify-changes.sh > /tmp/old-classify.sh
$ bash /tmp/old-classify.sh --files-from /tmp/paths
docs-only

$ internal/ci/classify-changes.sh --files-from /tmp/paths
source

$ printf 'docs/reference/runtime.md\n' > /tmp/paths     # positive control, same directory
$ internal/ci/classify-changes.sh --files-from /tmp/paths
docs-only
```

`test_classify_changes.sh` gained four expectations (the generated page alone, both prose neighbours,
and a set mixing the generated page with prose, which must be `source`) and holds 38; every new one
fails against the pre-fix classifier, which is what the control above shows.

**Cost, deliberately accepted:** regenerating the page after a CLI change now runs the full suite.
That is the right price for a generated artefact, and the alternative was a guard that could not run
on the path where the drift enters.

(`sol up`/`sol deploy` resolving the contract by workspace name rather than path) filed the same id
