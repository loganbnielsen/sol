Reject duplicate migration versions and stop treating `*.down.sql` as a required migration

**Depends on:** None.

**Finding:** FND-0032 (`internal/pipeline/audits/findings/`).

**Premise verified 2026-09-23** against `origin/main @ f3e9480b` while filing (see the finding for the command/probe and observed output).

## Problem

Migrations are keyed by integer version in both the pg-eio runner (`pending` filters on version; table PK is `version`) and Sol's deploy gate (`Sol_cli_migration.unsatisfied`). A second `NNN_*.sql` added after `NNN` is applied is never run and the gate reports OK. Sol's `required` also counts `NNN_x.down.sql` as a required migration, which only the version-only comparison makes harmless. Reproduced — see FND-0032.

## Remediation

Reject duplicate versions at read time in Sol's `required` (error names both files) and in pg-eio's `read_migrations`; exclude `*.down.sql` from `required` as the runner does; optionally compare `(version, name)` in the gate.

## Acceptance criteria

- `Sol_cli_migration.required` on a dir with `001_a.sql` + `001_b.sql` returns `Error` naming both files.
- `required` ignores `*.down.sql`.
- pg-eio `Migration.apply`/`status` reject duplicate versions (change lands in `~/Code/pg-eio`, pin bumped).
- Mutation check per `audits/README.md`: removing the duplicate check makes the new test fail with a successful build.
- Demo/example: the scaffolded `db/migrations` convention is unchanged; note in completion notes.
