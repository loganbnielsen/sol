Preserve External Secrets selection in emitted GitOps artifacts

**Depends on:** None.

**Premise verified (2026-09-28):** Traced `cli/bin/cmd_deploy.ml:176,298,499; cli/lib/deploy/sol_cli_factory.ml:29; cli/lib/deploy/sol_cli_executor.ml:81` and representative callers/tests at origin/main `6eb36b2c`. The audit records reproduced behavior, positive controls and practical limits.

## Problem

The CLI accepts External_secrets and dry-run renders the chosen ExternalSecret/store. Actual Emit_to execution unconditionally replaces the selected backend with Kubernetes_placeholder, emitting an ordinary blank Secret. Applying the artifact prevents ESO from supplying credentials and can overwrite existing values with blanks. Preview and actual output disagree while both exit successfully.

## Remediation

Preserve safe External_secrets and Kubernetes_placeholder backend choices through emission. Reject Kubernetes_live at the shared artifact boundary rather than overriding every backend. Keep CLI and library callers on the same safety contract.

## Acceptance criteria

- The same deploy command in dry-run and actual --emit-to preserves ExternalSecret kind, store reference, key prefix and refresh interval, with no ordinary Secret for that workload. Kubernetes_live cannot emit plaintext. Add a shared executor regression and update a runnable GitOps/ESO example; record no language-specific application-contract divergence.
- Completion notes identify runnable example/demo coverage and the per-language capability verdict, or explain why either is not applicable.
