## Friction log

1. **Root-only apt prerequisites.** `librdkafka-dev`, `libpq-dev`, `docker.io`
   all missing and `sudo` is not passwordless. *Workaround:* handed the install
   commands to the operator. *Blocks two-minute claim?* no (one-time setup), but
   blocks everything until done.
2. **Kubernetes tooling install assumes root.** The runbook's k3d one-liner
   targets `/usr/local/bin`; `helm`'s is the same; `kubectl` has no install
   command at all. Setting `K3D_INSTALL_DIR="$HOME/.local/bin"` still ended in a
   `sudo` password prompt ("Failed to install k3d"). *Workaround:* downloaded the
   pinned release binaries directly into `~/.local/bin`.  → FRIC-019
3. **OCaml toolchain.** `dune-project` requires `ocaml >= 5.4.0` but the only
   switch was 5.1.1; the opam index was stale enough that `ocaml.5.4.1` was
   "no package matching" until `opam update`; the new switch had no `dune`.
   *Workaround:* `opam update` → `opam switch create 5.4.1` → install `dune`.
   → FRIC-016
4. **External `*-eio` packages undocumented.** `sol.opam` needs 11 packages;
   six are not on opam (`obs-loki-eio`, `obs-tempo-eio`, `pg-eio`, `s3-eio`,
   `dynamodb-eio`, `lambda-eio`) and must be pinned from GitHub. Only
   `.claude/CLAUDE.md` (agent-facing) says so. *Workaround:* `opam pin add` all
   11 from `github.com/loganbnielsen/*`, then
   `opam install --deps-only --with-test <sol>`. → FRIC-016
5. **Silent workspace-name normalization.** `sol new workspace dogfood-2026-09-13`
   created `dogfood_2026_09_13/`, but Kubernetes namespaces are
   `dogfood-2026-09-13-*`. No warning. → FRIC-022
6. **Generated instructions name commands that don't exist.** The scaffold's
   "Next steps" and the generated workspace `README.md` both say `sol dev up`
   (README also `sol dev run`); `sol dev` is gone (REFAC-083), as is
   `sol local up`. The real commands are `sol local infra up` / `sol local run`.
   → FRIC-015
7. **Docker 29 vs k3d v5.6.0.** `sol local infra up` failed in 0.05s:
   `client version 1.43 is too old. Minimum supported API version is 1.44`.
   *Workaround:* `export DOCKER_API_VERSION=1.44`. The runbook lists Docker 29.x
   and k3d v5.6.0 as a tested pair. → FRIC-017
8. **`sol up` needs buildx.** Ubuntu's `docker.io` ships the legacy builder and
   no buildx plugin, so `--provenance=false --sbom=false` is
   `unknown flag: --provenance` (exit 125). *Workaround:* installed the buildx
   plugin into `~/.docker/cli-plugins/`. → FRIC-018
9. **`sol status` is not the local command.** Runbook step 6 and the skill both
   say `sol status`; it errors and says use `sol local status`. → FRIC-020
10. **`sol migrate --table` guidance diverges from the default.** Docs say
    `--table <workspace>_migrations`; the tool default is
    `sol_<workspace>_schema_migrations`. → FRIC-021
11. **Worker logs are invisible via `kubectl logs`.** The worker logs
    "charge event received" through `Sol_obs.log_info`, and the line *is* in Loki
    (`{service=~".*notify.*"}` → `level=info msg="charge event received" ...
    trace_id=...`), but `kubectl logs deploy/notify-worker` is empty — the
    runbook's own diagnostics path. → FRIC-023
12. **Duplicate charge IDs.** Both workspaces' first `POST /charges` returned
    `ch_770445`; the generated handler uses `Random.int` without
    `Random.self_init`. → FRIC-026
13. **Port-forward collision.** Port-forward state is keyed only by service name
    (`pf-charge-svc.*`) and hardcodes `:8080`, so deploying a second workspace
    cannot start its own forward. *Workaround:* killed the first workspace's
    forward before deploying the second. → FRIC-025
14. **`/usr/games/sol` shadowing.** Ubuntu ships a solitaire game named `sol`;
    with the built binary not first on PATH, `sol --version` →
    `Unknown option --version`. Hit it via `sg docker -c` (`/bin/sh`, so
    `source` of the env file failed). → FRIC-028
15. **Generated Dockerfiles cite `~/Code/CLAUDE.md`.** An internal contributor
    path appears in user-facing generated code. → FRIC-027

## Findings

- The two-minute claim is **conditional**: it holds only once the Docker image
  layers are warm (fresh workspace #2: 26.1s). A genuinely first-ever workspace
  pays ~5.5 min in `sol up`, dominated by pulling
  `ocaml/opam:ubuntu-24.04-ocaml-5.4` and doing apt + `opam pin`/`opam install`
  *inside the image*, once per image. See FRIC-024.
- The **error messages sol itself raises are good** (`sol status` names
  `sol local status`; `sol up` prints its run-log path; `sol migrate` announces
  its port-forward). The gaps are docs/prerequisites, not the CLI's error style.
- The worker→Kafka→DB path is genuinely proven: only `notify_worker` writes the
  notifications table, so the `/notifications` row cannot have come from the svc.
