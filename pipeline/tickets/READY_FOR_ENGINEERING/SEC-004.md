**Depends on:** DEC-026, DEC-027.

## Production guarantee

A production workload receives no ambient Kubernetes credential unless its
declared capability requires one, and supported runtime credentials can be
rotated through the selected reconciliation path without undefined behavior.

Per-workload ServiceAccounts, NetworkPolicies and Secret/ExternalSecret support
already exist. The generated ServiceAccount does not disable token automount,
and no existing ticket owns runtime credential rotation. FEAT-053 covers
build-time secret declarations and is not a substitute.

## Decision boundary

Engineering must decide the smallest Sol-level declaration for a workload that
genuinely needs Kubernetes API access and the supported rotation mechanism for
the authority selected by DEC-027. Do not expose service-account token or secret
volume implementation knobs as the application semantic.

## Implementation scope

- Disable ambient service-account token automount by default.
- Add an explicit, reviewable capability only if a supported workload needs API
  access.
- Define the runtime-secret refresh/restart behavior Sol actually supports.
- Keep workload identity federation, service-to-service authorization, admission
  policy and multi-team RBAC out of maturity A.

## Conformance and acceptance criteria

- A default workload pod has no Kubernetes API token mounted.
- A declared API-access exception, if supported, receives only the documented
  permission and is denied an unrelated operation.
- Rotating a representative database or API credential causes new application
  use of the new value, revokes the old value and returns the workload to healthy
  state without hand-editing generated manifests.
- Logs, plans, release records and conformance evidence contain no secret value.
- HARDEN-002 records the credential-rotation result.

**Demo/example coverage:** The production-profile example documents the supported
rotation operation using disposable credentials; no real secret is committed.

**TypeScript parity:** Credential injection and rotation are platform semantics
and apply equally to every supported language.
