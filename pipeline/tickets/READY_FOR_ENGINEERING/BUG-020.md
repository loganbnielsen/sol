**Depends on:** None.

Generated per-service Ingress resources set `ssl-redirect: "true"` but carry no TLS block and no cert-manager issuer annotation, so an exposed service redirects clients to HTTPS without ever serving a certificate.

## Problem

`ingress_doc` (`cli/sol/lib/sol_cli_manifest_yaml.ml:712-740`) is the only generator for a service Ingress (`cli/sol/lib/sol_cli_deployment_render.ml:220`) and emits only:

    annotations:
      nginx.ingress.kubernetes.io/ssl-redirect: "true"

It has no `spec.tls` entry and no `cert-manager.io/cluster-issuer` annotation. The platform ingresses that do carry the issuer annotation are the Argo CD and Grafana ones in `cli/platform/infra/base/main.tf:184,861`; a `cluster_issuer` variable exists there (`cli/platform/infra/base/variables.tf:6`), but the CLI has no knowledge of an issuer name (`rg cluster_issuer cli/sol` → no hits).

The surrounding pieces are in place — `platform/infra/base` installs ingress-nginx and cert-manager plus a ClusterIssuer, and the cloud modules create the DNS zone and cert-manager IRSA — so the net effect is that any workload with `ingress_host` set in `sol.toml` gets an Ingress that 308-redirects HTTP to HTTPS and then fails the TLS handshake. The docs promise "ingress/TLS wiring" as something Sol decides (`docs/planning/ROADMAP.md:141`).

## Goal

A service with `ingress_host` configured is reachable over HTTPS with a cert-manager-issued certificate, using the cluster's configured issuer.

## Remediation

- When `ingress_host` is set, emit a `spec.tls` block (`- hosts: [<host>]`, `secretName: <name>-tls`) and the `cert-manager.io/cluster-issuer: <issuer>` annotation.
- Thread the issuer name into the CLI's render inputs (e.g. a `sol.toml` field or an environment-target setting) with a documented default, since the CLI currently has no notion of it.
- Leave host-less (path-only) Ingresses without TLS/`ssl-redirect`, as today.
- Add a render unit test asserting the TLS/issuer fields appear exactly when `ingress_host` is set.

## Acceptance criteria

- `sol up --dry-run` / the deployment plan JSON for a svc with `ingress_host` shows a `tls` block and the issuer annotation; a host-less svc shows neither.
- On a cloud cluster, `curl https://<host>/health` completes with a valid certificate.
- A unit test covers both the host and host-less cases.
