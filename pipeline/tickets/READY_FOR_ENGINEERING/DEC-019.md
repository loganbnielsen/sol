**Depends on:** None. Constrains DEC-016 (deployment model), DEC-017 (diagnostics surfaces) and DEC-018 (rollback).

Decide where the hosted platform lives, and what interface this repository must expose for it to exist.

## Decision

**The hosted platform is its own repository** — its own application, its own release cadence, its own tickets. This repository is the open-source tool plus the interface the platform consumes.

**Stays here:** the CLI; the `-svc`/`-worker`/`-fn` framework; the `@sol/*` packages; the per-customer Terraform modules in `cli/platform/infra/`; examples; docs; dogfooding.

**Moves out:** the control plane and tenancy orchestration; the builder and runner, including worker isolation, image building, caching and build-log retention; the delivery pipeline; the dashboard; metering and billing; the platform's own infrastructure.

**Name: `sol-cloud`** — matching the product it vends.

**The platform's own backend is hosted on Sol** (dogfooding), so the first real customer of the hosted product is the product. Two consequences worth stating now:

- **There is a bootstrap problem.** The control plane cannot deploy itself from nothing, so a manual path has to exist first — Terraform plus an initial CLI-driven deploy — before the platform's own pipeline can manage the platform. Whatever that first path is, it stays documented and working rather than becoming a closed loop nobody can break out of.
- **Dogfooding is also the harshest test.** A platform bug breaks the platform, so the blast radius of a bad release is the ability to release. That argues for a deliberately boring first topology.

**Business and go-to-market content lives in `sol-cloud`** — the GTM plan, pricing and packaging, positioning, provider economics, hosted tenancy. This repository carries product and engineering content only. Note that this is a *forward* rule; existing material of that kind in the tree is handled by the history work (INFRA-009).

**The control plane's architecture is a `sol-cloud` decision**, including whether its compute is on-demand rather than long-running — to be discussed when that work starts. The relevant tension is that Sol's primitives are long-running services with a per-customer substrate floor, while on-demand compute is what makes an idle control plane free; the answer may differ for the control plane and for customer workloads.

**Visibility: the platform repository is private**, and it also carries the customer-facing web surfaces — the website, and later account and billing pages. Three rules follow:

- **The dependency is one-way.** The private repository may consume this one — released artifacts, the Terraform modules, the interface contract below. This one must never depend on, require, or link into anything private. A public Apache-2.0 product that needs private code is not open source in any meaningful sense.
- **Nothing in this repository may reference a private resource.** A public doc, comment or ticket pointing at a private repository, dashboard or runbook is a dead end for every outside reader — so this applies to documentation and tickets at least as much as to code.
- **One repository, several independently deployed surfaces.** The website, the dashboard, the control plane and the builder share a home because they share context — design system, copy, content. They must not share a release train: a landing-page change must not be able to ship the control plane, or the reverse.

**Why:**

- It matches this project's existing one-repo-per-concern pattern — `aws-eio`, `s3-eio`, `pg-eio`, `obs-*`, `lambda-eio` are all separate repositories.
- The trust and release properties differ sharply: the platform holds customer source and cluster credentials and is not public; this repository is Apache-2.0 and published.
- Hosted code has already been spiked here and deliberately removed (FEAT-010, modules removed 2026-06-22), so this re-affirms a decision rather than making a new one.

## The contract this repository owes

- **Deploy by digest** (`--image-ref`): the platform builds; the tool deploys what it is handed (FEAT-050).
- **Explicit target and environment selection, failing closed** (DEC-016).
- **Machine-readable plan output.** `--emit-plan-to` is the platform's integration point with the CLI, so its shape is an interface held to the same care as a public API — not a debug flag.
- **Release identity sufficient for rollback** (DEC-018).
- **`SOL_ENV` injection** for application behaviour only (DEC-016).
- **Build-time secret declarations**, exported by name and never by value (FEAT-053).
- **Versioned releases.** The platform consumes released versions of the CLI, framework and modules rather than a submodule or a local path, so a release process is a prerequisite for it.

**Not owed:** anything in the "moves out" list. Those requirements stay recorded in DEC-016 (which is where the build decision lives), but their tickets belong to the platform repository.

## Consequences

- The builder family filed under this repository is superseded: FEAT-051 (worker isolation), FEAT-052 (incremental builds) and FEAT-054 (build metering) are deleted here and belong to the platform; FEAT-050 and FEAT-053 are re-scoped to their CLI halves.
- The platform repository starts without these tickets and files them from DEC-016 and this decision.
- Testability differs by side: the contract above is testable in this repository's CI; the platform's builder is not testable without platform infrastructure.

## Handover to `sol-cloud`

Ticket content that is business, pricing or platform work rather than product work. These have moved to the private platform repository (DEC-019), together with their pre-reset history; what remains here is the constraint each one placed on the product.

| Ticket | Why it moved |
|---|---|
| `DOCS-015` (GTM plan) | Positioning, ICP, pricing and packaging are business decisions |
| `DEC-011` (hosted provider policy) | Provider economics per tier is a business decision; the *constraint* it produced already lives here in DEC-016 |
| `DEC-014` (spend ceiling and billing model) | Pricing and billing are business decisions |
| `INFRA-004` (hosted tenancy prototype) | Proves the platform's own mechanism in Sol's account |
| `FEAT-049` (spend-ceiling enforcement) | Per-tenant attribution, alerting and enforcement are platform operations |

**Mixed, staying here with a narrower scope** — these cannot simply move because the tool-side half is genuine product work:

- `INFRA-006` — the cheap-substrate recipe and credential story is self-hosted product work; the cost table it produces is a business input and travels with `sol-cloud`.
- `FEAT-048` — an edge integration serves self-hosted users too; which provider the *hosted* tier uses is business.
- `SOL_ENV`, target selection, digest deploys, rollback identity — the CLI contract in the section above, which is product work by definition.

**Not a mechanical deletion.** Five further tickets reference these (`DEC-016`, `DEC-018`, `INFRA-006`, and historically `REFAC-071`/`REFAC-076`), so the move is one coordinated pass: copy into `sol-cloud`, fix or inline every dangling reference — a public document must not point at a private one — then delete here, then reset the history.

## Acceptance criteria

- No ticket in this repository's pipeline depends on platform-only infrastructure.
- The CLI can deploy a prebuilt digest without building, and its plan output is consumable by a platform.
- The contract above appears in the CLI's help and documentation, not only in this decision.
