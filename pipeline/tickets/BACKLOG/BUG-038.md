`soldev pipeline merge-finish` writes a commit branch protection always refuses

**Depends on:** None.

## What happens

`soldev pipeline merge` succeeds, then `merge-finish` commits the updated
`devtools/perf/perf_baseline.json` straight onto local `main`. Pushing it fails:

```
! [remote rejected]   main -> main (protected branch hook declined)
```

The merge itself is unaffected — the PR is merged before this runs — but every
merge leaves local `main` one commit ahead of `origin/main`, and that commit can
never be pushed. Observed on #308; it is not specific to that PR.

## Why the documented workaround does not apply

`.claude/CLAUDE.md` records a bookkeeping exception for "direct-to-`main`
ticket-file commits (`BACKLOG` promotions, audit filings) — kept outside PRs
because they are metadata moves, not code." Branch protection declines those the
same way, so the exception describes a path that no longer exists. This ticket
was itself filed on a branch for that reason.

`--admin` would push it through, and should not be used: bypassing a protection
rule to record an informational timing number is a bad trade, and normalising the
bypass for the cheapest possible artifact is how it ends up used for expensive
ones. Dropping the commit (`git reset --hard origin/main`) is currently correct —
the baseline is main-only, informational, and regenerable with
`run_tests.sh --update-baseline`.

## Remediation

Pick one; they are ordered by preference.

1. **Record the baseline in the PR, before merge.** The numbers are known when CI
   runs; making them part of the branch means the squash carries them, exactly as
   ticket `DONE/` moves already work. Removes the post-merge commit entirely.
2. **Persist it off `main`** — a git note, a branch that is not protected, or a CI
   artifact. Keeps it informational and out of the protected history.
3. **Stop committing it.** Report the comparison in `merge-finish`'s output and
   let `--update-baseline` remain the only writer.

Whichever is chosen, `merge-finish` must not leave local `main` diverged from
`origin/main`, and `.claude/CLAUDE.md`'s direct-to-`main` bookkeeping exception
needs correcting in the same pass — including for ticket filings, which is the
other thing it claims works.

## Acceptance criteria

- A full `soldev pipeline merge` leaves local `main` equal to `origin/main`.
- No path in `soldev` passes `--admin` for perf-baseline bookkeeping.
- `.claude/CLAUDE.md` describes how ticket-file bookkeeping actually reaches
  `main`.
- Demo/example coverage: not applicable — this is internal developer tooling with
  no app-author-facing surface.
