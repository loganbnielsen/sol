**Depends on:** INFRA-006 (the recipe and cost evidence this should be decided with).

Decide whether the hosted substrate's *provider* is fixed to AWS, or a per-tier choice.

**Question:** DEC-008 fixed the hosted tenancy *mechanism* — one Sol-owned AWS account, a per-customer VPC and cluster, provisioned through `platform/infra/aws` with per-customer Terraform state — and its criteria already weighed "the cost floor per customer (a dedicated EKS control plane alone is a real fixed cost) ... in tension with a 'cheap for small projects' pitch". Cheap managed-Kubernetes providers move that arithmetic by roughly an order of magnitude: Hetzner is ≈ €17/mo for a 3-node cluster plus a load balancer with 60 TB of included egress, against EKS ≈ $73/mo per customer *before* nodes and before the ALB/public-IPv4/NAT layer. Does the hosted path stay AWS-only, or does provider become a per-tier choice?

**Scope:** this reopens DEC-008's *provider* half only. DEC-008's mechanism (Sol-owned account, per-customer isolated substrate, Terraform module, per-customer state) is provider-agnostic and survives a provider change. DEC-002 is not in question — a cheaper tier still means a per-customer cluster/network, never a shared cluster with namespace-level isolation (which is DEC-008 option 3, already rejected).

**Options:**

1. **AWS only** (status quo, DEC-008). Managed Postgres/Kafka, compliance attestations, wide region coverage; highest per-customer floor.
2. **Provider per tier.** AWS/GCP for the compliance/isolated tier; a cheap Cilium/Calico-backed provider for the standard hosted tier, still per-customer isolated. Costs one additional Terraform module — justified because it serves Sol's own product rather than user-facing provider breadth (which the bring-your-own-cluster path already covers).
3. **Cheap-first**, with AWS as an exception path for compliance-constrained customers.

**Decision criteria:**

- Per-customer cost floor against the Vercel-style "cheap to start" positioning DEC-008 named.
- Whether capturing the saving requires Sol to self-host the substrate (Kafka/schema registry, Postgres, observability) and what that costs in durability/on-call work. `sol dev up` already installs those charts, so the delta is productionising them, not building them.
- Compliance: cheap providers do not offer SOC 2 / HIPAA BAA / PCI inheritance. Which customers can be served there at all?
- Regions and residency, provider concentration, and support/SLA posture for a product that may advertise an SLA.
- DEC-002 consistency: per-customer isolation must hold on whatever provider is chosen.
- BUG-022: any k3s-based provider (e.g. Civo) uses kube-router, which does not enforce the NetworkPolicies that isolation rests on. In a multi-tenant setting that is a security issue, not a failing test.

## Decision

**Provider per tier.** A customer chooses compliance-grade (AWS/GCP, higher price) or standard (a cheap Cilium/Calico-backed provider, lower price). Isolation is identical either way — one isolated cluster/network per customer — so DEC-002 holds and DEC-008's mechanism (Sol-owned account, Terraform module, per-customer state) is reused per provider rather than revised.

This revises DEC-008's **provider half only**, which DEC-008 itself flagged as in tension with a "cheap to start" pitch. DEC-002 is untouched.

**Explicitly not decided here — and why no number can be quoted yet:** the *pricing model*. The tier decision fixes the cost **floor**; it says nothing about the **exposure**. Usage-driven cost (egress, data processing, request volume, storage) scales with the customer's traffic and lands on Sol's bill, so a flat price over unbounded usage is an unbounded liability. Filed as **DEC-014**.

Sequencing: pick the actual cheap provider when INFRA-006 lands its cost table and the first hosted customer's compliance profile is known. A customer who cannot be served on a cheap provider (no SOC 2 / HIPAA BAA / region coverage) defaults to the compliance tier — which is a better way to resolve this than choosing a provider in the abstract.

**Acceptance criteria:** the provider policy is named ✅ and reconciled with DEC-002/DEC-008 ✅; the per-tier cost figures land with INFRA-006, and the charging model with DEC-014 ⏳.

**Acceptance criteria:**

- A written decision names the provider policy and states the expected minimum per-customer cost per tier.
- It reconciles explicitly with DEC-002 (isolation) and DEC-008 (mechanism), or states which of them it revises.
- Follow-up tickets are identified for any new provider module and for the DNS/TLS credential path where no cloud IAM exists.
