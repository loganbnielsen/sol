**Depends on:** None.

`Sol_cli_cmd_new.infer_sol_home()` can resolve `_build/default` as the Sol checkout root instead of the real source checkout, breaking SOL_HOME-sensitive CLI tests whenever framework sentinel files exist under the build tree.

## Problem

`infer_sol_home()` (in `cli/sol/lib/sol_cli_cmd_new.ml`) walks up from the running executable's directory and accepts the first ancestor containing both:

- `framework/sol-svc/lib/dune`
- `framework/kafka-eio-service/lib/dune`

When a test executable runs from `_build/default/cli/sol/test/`, `_build/default/framework/sol-svc/lib/dune` and `_build/default/framework/kafka-eio-service/lib/dune` can both exist — e.g. after `dune fmt` has run the formatter over the framework tree, or after framework paths have been built/tested in the same build context. The ancestor walk then stops at `_build/default` and treats the build directory as Sol home.

Observed failure modes during INFRA-006:

- `test_dev_observability` tries to read dashboards from `_build/default/cli/platform/infra/base/dashboards/…`, which does not exist, and fails.
- `test_scaffold` symlinks `testapp/vendor/framework` → `_build/default/framework`; dune then sees both source rules and generated artifacts in the same directory and fails with `Multiple rules generated` / "file present in source tree".

This was first exposed in CI when INFRA-006 ran `dune fmt --preview` before `dune build`: the formatter populated `_build/default/framework`, and the CLI test job failed even though the same command sequence passes from a clean checkout without that pre-population. The ticket worked around it by moving the format check after unit tests, but the underlying resolution bug remains latent: any future step that populates the build tree before these tests can reintroduce the failure.

## Goal

`infer_sol_home()` must never return a build-context directory (`_build/...`) as the Sol home. The CLI test suite should behave deterministically regardless of whether framework sentinel files already exist under `_build/default`.

## Remediation

- Make `infer_sol_home()` reject candidate roots that look like build directories, or require an additional source-root marker (e.g. `dune-project` at the candidate root, or the repo's `.git` directory) alongside the two framework sentinels.
- Keep `SOL_HOME` as the explicit override when set.
- Add a regression test that constructs a fake `_build/default/framework/{sol-svc,kafka-eio-service}/lib/dune` ancestor layout and asserts `infer_sol_home()` does not select the `_build/default` candidate.

## Acceptance criteria

- `dev_observability` and scaffold compile tests pass even when `_build/default/framework/...` already contains the two sentinel `dune` files.
- A unit test covers the "ancestor looks like a build dir" case.
- No existing `SOL_HOME`-explicit behavior changes.
